# VC5 matching lessons

Reusable empirical findings about Microsoft Visual C++ 5 code generation.

## Diagnostic signals

- Verify direct-call target identity before copying a same-named donor ABI.
- Ordered call-site and relocation parity matter. Call counts alone do not.
- Exact size, frame, calls, and CFG do not prove exact structure.
- A small edit diff with a large positional diff often marks one shifted hunk.
- One SIB byte can change instruction size and all later branch spans.
- PDB line bands can identify declarations, initializers, and loop updates.
- Recompute ESP-relative homes after every push, cleanup, and callee-cleanup call.
- Decompiler stack names can merge, split, or transpose source variables.
- Track fixed entry addresses when pushes change `[esp+N]` labels.
- Repeated identical output identifies one compiler basin. Change hypothesis class.
- A worse metric can still reveal the controlling source feature.

## Scope, declarations, and liveness

- Declaration scope, order, and initialization site affect complete VC5 output.
- They control scheduling, stack homes, saved registers, and prologues.
- Earlier call-crossing locals often win scarce callee-saved registers.
- Declaration order can control entry register colors for independent object graphs.
- VC5 can still emit their loads in the opposite order.
- A top-level local and a nested local can produce different frames.
- A `for`-header index can differ from a separately declared index.
- Split declaration from assignment when the original delays a zero store or LEA.
- Join declaration and initialization when the original materializes a value early.
- Put address-taken outputs at function scope when nested declarations let loads hoist.
- Declare a value inside a successful guard when the original saves it only there.
- A late zero local can keep a zero register live and add a saved register.
- An early `= 0` can let VC5 rematerialize zero and reduce pressure.
- Named locals preload fields, enable CSE, and extend liveness.
- Direct member expressions delay loads and preserve repeated member reads.
- Keep a local when assembly carries one value through a phase.
- Use direct access when assembly reloads a member after calls or branches.
- Use fresh member access to preserve a binary-observed redundant null test.
- Separate sibling guards when nesting lets VC5 remove a required recheck.
- Kill an incoming parameter after its first member store when assembly reloads the member.
- Reusing the parameter can keep it live and change the complete frame.
- A mid-loop reassignment can force a spilled variable into a saved register.
- Use a separate short-lived call argument when the replacement feeds one call.
- One large expression can preserve result registers across calls or arithmetic.
- Split expressions when assembly proves a call or argument boundary.
- Post-increment, compound assignment, and expanded assignment are distinct VC5 inputs.
- `a()*b()` can preserve the first result where staged multiplication does not.
- A named `param + 1` limit can change pre-loop LEA and base-load order.
- One plausible intervening declaration can prevent an early count-read hoist.
- A named byte count can let VC5 push the size before an independent store.
- A named aligned value can remain live across its store and next guard.
- Mutating an accumulator in place can preserve it across a timestamp call.
- For elapsed formatting, zero output parts before the timestamp call.
- Use one signed elapsed value afterward to preserve signed quotient and remainder.
- Reuse one clipped or result local when a later fallback replaces that value.
- A second `new_*` local can add a spill and change its saved register.
- A function result used only as a predicate should usually remain in the predicate.
- Remove result temporaries when they add artificial call-crossing liveness.
- Keep a named result when assembly carries it into later work.
- A local reference can preserve a real load/store pair or field alias.
- Retain such an alias only when the surrounding bytes prove its need.
- A direct member assignment and a chained assignment can coalesce differently.
- Two equal byte locals can need two separate member assignments to keep two homes.
- A branch-local typed global receiver can block cross-arm global-load CSE.
- Name a fetched record before its byte test when assembly carries that pointer.
- Independent stores can reorder. Source order can be opposite emitted order.
- Try a real dependency or direct reread before volatility.
- A comma expression can alter preload and store timing.
- Keep it only for a plausible, binary-supported evaluation order.
- `register` on a read-only parameter can change EAX/EDX versus ESI/EDI use.
- Do not apply `register` to address-taken parameters.
- Narrow volatility can diagnose CSE, hoisting, or a required reread.
- Do not retain fake volatility or unused locals for metrics alone.
- A late block can change the prologue by crossing a pressure threshold.
- If deleting a late block fixes an early register mismatch, inspect long-lived temps.
- Repeated member reloads can cycle store registers where one saved pointer cannot.

## Types, ownership, layout, and addressing

- Establish width, signedness, ownership, offsets, alignment, stride, and `sizeof` early.
- Model pointer members as pointers and inline arrays as inline arrays.
- Include vptrs, base sizes, tail padding, and derived alignment.
- Derived fields start at aligned `sizeof(Base)`, not the last visible base field.
- Use a narrow flat overlay only for a proven access in base tail padding.
- A full typed class surface can change allocation with unchanged touched offsets.
- Model proven subfields directly. Do not invent helper objects or vptrs.
- Replace local gaps with canonical types when wider evidence stabilizes.
- Preserve real inheritance for EH, vptr, and base-call context.
- Use one raw field access only when vtordisp or uncertain layout requires it.
- Correct aggregate size can unlock whole-struct base-pointer copies.
- Protocol size can differ from padded `sizeof`.
- Use aggregate assignment when the executable copies all bytes.
- Use field copies when it omits padding or narrows the final copy.
- Proper fields can fold address calculation and extension better than raw views.
- A relation or flag table loaded through a member must be a pointer field.
- Typed `resourcePtrs[type][i]` and `numResources[type]` can avoid duplicate loop compares.
- Casted base and current pointers can create an extra bottom test.
- Real multidimensional arrays can recover fixed row strides and SIB forms.
- A one-based enum often maps naturally to `array[type - 1]`.
- Packed records can use an interior-field cursor with negative and positive offsets.
- Prove the owner, stride, and anchor before keeping this form.
- Keep sign-extended packed amounts as `int` when assembly spills them.
- Use typed `Queue[i].field` when VC5 strength-reduces record indexing.
- Replace decompiler cross-member cursors with one canonical indexed array when valid.
- Use one shared index for corresponding elements in parallel arrays.
- Use one moving cursor when all observed offsets stay relative to one base.
- Direct repeated indexing can reduce row-pointer liveness.
- A typed row and biased tile pointer can preserve row and neighbor addressing.
- Address term order can change SIB base, index, size, and branch spans.
- Some pointer-plus-int terminator stores are canonicalized. Stop testing dead axes.
- A global byte-offset base can need `extern char*`.
- A symbol-relative buffer can need `extern char buffer[]`.
- Prefer reviewed extern globals over absolute dereference macros.
- Absolute access can change relocation, scheduling, and register allocation.
- `rge_base_game` uses the reviewed extern surface unless target evidence differs.
- Keep external read-only tables `const`. Local copies change data and relocations.
- A flat local vtable view must account for its own vptr.
- Prefer the real inherited virtual surface when known.
- Declaration-only padding slots are acceptable for a narrow local virtual surface.
- Model direct members as nonvirtual and vtable dispatches as virtual at exact slots.
- A late virtual fallback can be separate from the direct method under recovery.
- Preserve helper arity, overload, convention, return width, and ownership.
- PDB `__thiscall` with `ret N` requires a real member definition.
- An explicit self stack argument with caller cleanup indicates cdecl or static use.
- Narrow virtual parameters can prevent caller extension when ABI evidence supports them.
- A byte member passed through an `int` ABI can emit `xor eax,eax; mov al,[member]`.
- A byte-typed helper can remove the required zeroing and change scheduling.
- A virtual numeric getter feeding `__ftol` can return `float` on ST0.
- Struct-return initialization passes the destination directly.
- Struct-return assignment can use a temporary and aggregate copy.
- A by-value three-int point is not three independent scalar parameters.
- A typed `XYPoint` can recover adjacent coordinate homes and load order.
- A typed local aggregate can recover a proven contiguous stack window.
- Do not use an aggregate only as opaque frame padding.

## Parameters, homes, and local frames

- VC5 often reuses dead incoming parameter homes as local storage.
- If assembly writes and reloads a parameter home, try mutating that parameter.
- Save the original value only when later behavior needs it.
- Separate narrow outputs can coalesce onto full-width parameter homes.
- This often explains adjacent `fscanf` or API output LEAs.
- Source vararg destination order follows right-to-left lowering, not stack labels.
- Out-parameter cast spelling can select adjacent stack slots.
- Use the proven LEA displacements and actual output types.
- An incoming parameter can become a moving byte offset while a register tracks index.
- A declare-only output can coalesce with a dead parameter home.
- An invalid-path reload can imply original uninitialized behavior.
- Retain that behavior only with explicit binary evidence and a source comment.
- Adding an initializer absent from the executable changes stores, lifetime, and homes.
- A proven missing initialization can be original behavior, not incomplete reconstruction.
- Keep an early address-taken temp separate from later parameter-home reuse.
- A decompiler can fold a distinct terminator dword into `buffer[0]`.
- Restore a separate marker when the frame and string addresses prove it.
- One local-frame struct can lock adjacent C API objects and padding.
- Prefer named locals unless exact addresses prove the grouped window.
- A small buffer plus adjacent scalar can form one typed aggregate.
- Two floats plus one FPU integer can need a typed local window to fix slot rotation.
- A reported four-entry local array can have a real fifth contiguous slot.
- Model the complete array when a later pointer consumes that slot.
- `char buf[N]` near 4 KiB can trigger `__alloca_probe` without EBP under `/Oy`.
- `_alloca(N)` can force an EBP frame.
- Keep original C translation units as C. C++ mode changes linkage and codegen.

## Calls, imports, strings, and memory operations

- Use an imported function-pointer declaration for original IAT-indirect calls.
- Use a normal declaration for original direct relative calls.
- Relocation symbol identity is part of exactness.
- A branch-local function pointer can model observed IAT caching.
- Cdecl evaluates arguments right to left.
- Nested calls can interleave literal pushes, receiver loads, and helper calls.
- Split a helper when assembly completes it before setting up the next call.
- Keep nested source when assembly pushes literals before producing the receiver.
- A literal pushed before the call that produces `this` often needs one nested member expression.
- Saving that receiver first moves the literal push after its producing call.
- Put a width cast inside the call argument when extension timing matters.
- Attach each argument to the helper that consumes it.
- Wrong ownership can enable a tail jump or wrong cleanup.
- Member helpers must be members when ECX carries `this`.
- Infer complete C helper arity from stack use, not a decompiler prototype.
- `noreturn`, exception, import, and linkage attributes can change cleanup and epilogues.
- Treat these declaration attributes as compiler inputs, not descriptive comments.
- Use real period headers and declarations for CRT and API helpers.
- Natural `strcpy` can emit VC5's combined scan and REP copy.
- `strlen(x)` emits a decrement after the raw intrinsic count.
- `strlen(x) + 1` can cancel that decrement.
- `strcat` scans source before destination. `strcpy(dst + strlen(dst), src)` does not.
- A short-literal `strcmp` can inline a two-byte compare loop and `sbb` result.
- Variable-size `memcpy` can inline REP copies.
- Fixed aggregate assignment can emit a different REP setup.
- Fixed `memset` can preserve REP zeroing that aggregate initialization removes.
- A byte-replication fill can require loading only AL from an `int` seed.
- A local initialized string can emit literal dword stores and delayed zeros.
- Declaration line, buffer size, and call placement can affect this lowering.
- Natural float-to-long conversion calls `__ftol` with ST0 live.
- A fake `__ftol(float)` declaration introduces wrong spills and ABI.
- Float-forwarding wrappers need real float virtual getters and natural casts.
- Right-to-left evaluation can interleave getters, `fstp [esp]`, `__ftol`, and pushes.
- A moving source-string parameter plus an end pointer can recover filename loops.
- Keep nested global expressions in following vararg calls when push order proves it.
- Avoid naming `this + offset` buffer bases when direct expressions reuse ECX.
- A helper used only for success status should remain the guard.
- Reload the named object member when assembly does not preserve the API result.
- A virtual float result ignored by source still requires `fstp st0`.
- Declare the real return type even when callers ignore it.
- Two branch calls with one common argument can hoist that push before the test.
- A literal dispatcher with call-and-return arms can emit `push imm; jmp shared_call`.
- A selector local can instead emit `mov reg,imm` and change the tail.
- Duplicate both a call and its branch value when assembly keeps distinct pushes.
- VC5 can CSE the value while preserving separate call setup.
- Defaulted dropdown calls can need one source call in each arm and one merged call tail.
- A preassigned fallback can replace a required late immediate push with a move.
- Two emitted calls on one PDB line can come from one tail-duplicated source call.
- Try a common source statement before writing duplicate calls.

## Translation-unit context, globals, and flags

- Translation-unit context can change VC5 output without changing body semantics.
- Standard headers affect intrinsics, EH, allocator choices, and SIB encodings.
- A VC4.2 campaign found that unused file-scope declarations changed register output.
- Declaration kind and name length did not matter, while macros and unused members differed.
- Token-neutral include placement also changed output through front-end state.
- Treat these as old-MSVC context hypotheses until local VC5 evidence confirms them.
- VC5 can exhaust its inline budget partway through one large function.
- Early helper sites can inline while later sites call the same out-of-line body.
- When that split is proved, test helper visibility, `/Ob`, or function-scoped
  `#pragma inline_depth(0)`; the pragma can help one function and harm another.
- `<windows.h>`, real `RECT`, and API declarations can select another basin.
- `<stdlib.h>`, `<string.h>`, `<memory.h>`, and their combinations can do the same.
- A header combination can work when either header alone does not.
- Restore donor-supported period context before aliases, volatility, or raw cursors.
- Keep a winning header only when donor or API evidence supports it.
- Full SDK interfaces can change push and vtable-load scheduling at one called slot.
- The compiler version does not identify the historical SDK version.
- Include-path precedence can change declarations, vtable slots, and call targets.
- A local `tagRECT` clone can still differ from the SDK `RECT` basin.
- Correct typed world, player, master, or record ownership can alter allocation.
- Raw offset views at the same addresses can remain in the wrong basin.
- A named intermediate for `global->field->method()` can change absolute load encoding.
- Scope it to one call so it does not become callee-saved.
- Original compiler context is part of source recovery.
- VC5 service packs can change code generation across many unrelated functions.
- Isolate compiler binaries from headers and libraries during a version comparison.
- An original EH frame is strong evidence to test `/GX`.
- `/GX` can change frames, exits, vptr stores, cleanup, and whole-function scheduling.
- Debug-style EBP code can justify a focused optimization-flag experiment.
- A flag match still needs source, ABI, relocation, and policy review.

## Constructors, destructors, allocation, and EH

- Use real constructors, initializer lists, members, destructors, `new`, and `delete`.
- Match allocation size before tuning surrounding code.
- A derived allocation can be required for the derived-vptr store.
- Direct `new T(args)` can trigger `/GX` new-object state around the constructor.
- `new T; init()` can produce different state and cleanup.
- Plain C++ linkage for a throwing helper can enable base-subobject unwind state.
- `extern "C"` can suppress the required constructor frame.
- Visible virtual destructors can control EH frame generation.
- A real base initializer can recover vptr, state, and base cleanup.
- Match base-constructor overload and all mode arguments.
- Initializer-list execution follows declaration order.
- It can delay a derived-vptr store relative to body assignments.
- The first body use of a parameter can hoist its load before the vptr store.
- Prefer natural initializer order over explicit vptr plumbing.
- Use `novtable` plus one explicit vptr only as a narrow proven fallback.
- Real destructible members contribute EH state numbers and cleanup order.
- Model a four-word inline managed member when the binary proves its constructor state.
- A paired empty derived destructor can inline that member's destructor and call the base.
- Leave base destruction implicit unless assembly proves an explicit source call.
- Explicitly destroying an automatic object can cause duplicate destruction.
- Natural `delete member; member = 0;` can emit cleanup absent from raw delete helpers.
- Natural virtual destructor surfaces can place derived-vptr restore and base destruction.
- Manual vptr stores or base calls can reorder them or introduce thunks.
- Save a member pointer before its null check when assembly carries it across destruction.
- Reuse that pointer across destructor and delete when one saved register proves it.
- Several same-type heap members can each need this ordinary local shape.
- A vector-deleting helper can need one shared delete pointer and common epilogue.
- A destructor scanning adjacent pointer arrays can use indexed arrays and one cursor.
- Overlapping cursor tricks can add another saved pointer.
- Two exclusive destructor scans need separate branch-local cursors from one base.
- One cursor mutated in the first branch changes both behavior and register lifetime.
- Put a child-construction loop inside the positive-count allocation arm when proved.
- Pass stored context members when assembly reloads them after construction starts.
- An inline member's natural default constructor can recover delayed calls and vptr order.
- Move a final zero into the initializer list when only its order with the vptr differs.
- A common close call after a constructor branch can tail-duplicate correctly.
- Two explicit source close calls can change callee-save timing.
- Move independent sentinel-link stores later when initializer stores must interleave first.
- In a mask tail, source inverse-field order can control copy, shift, and store scheduling.

- Redundant predicates can be original and codegen-active.

- Member-left and parameter-left comparisons can load and branch differently.
- Truth tests and comparisons with `1` are not interchangeable.

- Explicit byte assignments can emit `setcc byte` without clearing a full register.
- One post-branch call can tail-duplicate into both arms.

- Duplicate or share source calls according to observed call-site count and layout.
- Assign one call argument in each arm when VC5 must coalesce branch accumulators.
- Scoped result locals in identical switch cases can preserve two API call sites.
- One function-wide result local can fold those calls into one site.
- Duplicate a conditional member call when branch-local pushes join at one receiver.

- An explicit success return plus fall-through fallback can preserve one merged call site.
- A single return after `if/else` can hoist the result into a saved register.
- Per-arm returns can use immediate EAX and form different epilogue groups.
- A final pointer store plus one return can preserve a saved output pointer.
- A `switch` and an `if` chain produce different dispatch and block placement.
- Late equality handlers often indicate switch cases after the main epilogue.
- Sparse switches can emit subtract, decrement, and reused equality tests.
- A switch on the original narrow value can preserve one-based mask/decrement lowering.
- Restore every natural dispatch before diagnosing unrelated handler merging.
- Source case order can control emitted handler order.
- PDB line order can reveal handler order when decompiler output sorts cases.
- Stacked case labels share one body. Separate cases can duplicate it.
- Use `break` to one post-switch return when the executable has a shared tail.
- Use per-case helper returns when helper tails are duplicated.
- Mixed return placement can produce required handler merge groups.
- A nested negative equality can place a rare handler late.
- A source-local label can place a shared switch failure or handler where proved.
- A hot case can jump to a later source label when PDB bands prove that order.
- A small outer switch can outline one large nested dispatch.
- Equivalent `if/else` can place the large body inline.
- A common assignment after `if/else` can tail-duplicate with per-arm registers.
- A direct member increment followed by a member threshold can store before compare.
- A derived `next` local can instead compare before the required store.
- Duplicate the assignment when it must be hoisted between compare and branch.
- Shared outgoing literals can hoist before branch tests.

- Cleanup can sit outside `if (Lock())` but inside an outer feature guard.

- A first-body bound plus a fixed while-bound can prevent test peeling.

- Direct success returns inside scans can remove post-loop index tests.
- Keep cursor updates in observed order.

- Mutating an incoming offset can reproduce two induction registers and home writes.
- A `for` increment list can preserve `inc index; add cursor,stride` order.

- Try ordinary `count++` and cursor-update order before aliases.
- Put pointer advancement before the body only when assembly does so.

- Descending loops can need `for (; index >= 0; --index)` and a signed backedge.
- Source-local found and next labels can preserve separate success and skip tails.
- A reverse scan can need an explicit negative guard before its walker LEA.

- A count increment followed by `break` can force final reload from its home.
- Direct return can keep EAX live and skip that reload.
- Reuse one loop local across scans when assembly reuses one home.
- Use separate locals when nonoverlapping lives coalesce into the desired home.
- A persistent count and first-pass countdown can change color with second-loop form.
- A loop-counter copy inside a positive guard can coalesce onto a dead parameter home.

## Floating point, arithmetic, width, and comparisons

- Trace the x87 stack and exact operands. Preserve original odd formulas and bugs.
- Repeated loads, asymmetric subtraction, or transposed axes can be intentional output.
- Float and double literals select different loads and comparisons.
- One function can intentionally mix float and double operations.
- `test ah,1`, `test ah,40h`, and `test ah,41h` test different x87 conditions.
- Infer the predicate from operand order and actual x87 stack state.
- Keep a value on ST0 when assembly carries it through several checks.
- A named temporary can force `fstp` and reload.
- Initialize FPU loop state where assembly loads it, not where source looks tidy.
- Parentheses can stop reassociation into another subtract family.
- A double-cast multiply can anchor left-to-right float multiplication.
- Explicit zero-minus-product can preserve `fchs` then `fadd` instead of `fsubr`.
- An explicit float cast around a negated product can preserve a rounding boundary.
- Keep these spellings only when x87 topology proves them.
- Inline a denominator call when original spills numerator then uses `fdivr`.
- Naming the denominator can add x87 shuffles and select `fdiv`.
- Bind a scaled virtual getter before `sqrt` when the scale remains live through the sum.
- A separate scale or post-sqrt multiply can move the constant operation.
- Branch-local integer calls converted to float can preserve two `fild` paths.
- One integer result followed by one conversion can tail-merge the calls incorrectly.
- A named float numerator can make VC5 materialize a signed divisor first.
- Literal thresholds can schedule x87 work differently from external rdata symbols.
- Use literal versus extern form according to the observed integer/FPU interleave.
- Apply a float facet step directly with `+=` or `-=` when assembly has one common pop.
- Threshold operand order can change `fld`, `fcomp`, and branch polarity.
- Clamp assignment order can control min/max x87 pop and store schedule.
- Use natural signed division and remainder.
- `/8` emits VC5 signed correction better than handwritten shift correction.
- Signed `% 2` or `% 4` is not `abs(value) & mask` for negative values.
- Natural constant division should produce VC5 magic multiply and correction.
- Width and signedness control extension, byte registers, compares, and branches.
- For unsigned bytes, `value <= 2` can emit compare-2/JBE where `< 3` emits compare-3/JB.
- Use `int mode = field; (char)mode` for dword load followed by AL compares.
- Use a widened short or byte result when assembly materializes it before a guard.
- A narrow local can let VC5 sink materialization past the guard.
- Use signed-byte run lengths for `test al; neg al; movsx` decoder patterns.
- An unsigned byte can add `and eax,0xff`.
