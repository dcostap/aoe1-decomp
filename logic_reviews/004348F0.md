# Re-review: 004348F0 `RGE_Command::do_command_add_attribute`

## Verdict

**BLOCKED.** Do not approve the current `accepted_drift` status. Keep the
natural source, but require a new status decision. No source repair is
approved.

## Behavior

The original body is 40 bytes. It has 16 instructions, no frame, one virtual
call, matching cleanup, and matching boundaries.

At entry, the original executes:

```text
004348F0  mov eax,[esp+4]
004348F4  mov ecx,[ecx+4]
```

The rebuild executes the same two loads in reverse order. The first original
load reads the argument-home pointer value. It does not dereference the
`RGE_Command_Add_Attribute` object.

For a valid `__thiscall`, both bodies read the same player ID, resolve the
same `world->players` entry, read the same attribute ID and float amount, and
call the player's virtual slot `+0x78` with the same arguments. This proves
valid-input semantic agreement only.

For malformed memory, the order is observable. If `this` is unreadable and
`[esp+4]` is readable, the original reads the argument home before it faults
at `[ecx+4]`. The rebuild faults at its first instruction before reading the
home. If `[esp+4]` is unreadable and `this` is readable, the original faults
at the argument home before loading `this->world`; the rebuild loads
`this->world` first. A fault handler can observe the faulting address,
instruction, and register state.

An invalid packet pointer alone does not create an earlier packet fault. Both
bodies load that pointer first or second, then dereference it at the same
later packet-field read. No runtime malformed-input test was run. The
instruction trace proves the initial access-order difference.

## Source and repair

The current typed source is the smallest source supported by the packet
layout, PDB stack record, class layout, and neighboring Command methods.
These natural forms were tested in the complete translation unit:

- PDB parameter name and historical direct-chain source;
- packet aliases;
- player-ID locals and split declarations;
- pointer dereference syntax; and
- a world local.

All supported forms emitted the same 40-byte body with the same five-byte
load-order mismatch. A volatile packet view emitted the desired first two
loads, but produced a 45-byte body, floating-point loads, changed register
saves and later operations, and failed the size constraint. It is artificial
and must not be retained.

## Status and integration

The old accepted-drift approval covered valid inputs only. The newly reviewed
fault cases disprove a behavior-equal claim over unreadable stack or `this`
memory. The target therefore remains blocked until original source or a
supported compiler-context donor recovers the order. Do not add inline
assembly, volatility, wrappers, raw addresses, or manual vtable code.

No source, header, flag, registry, or inventory change is approved by this
review. The registry still records the prior `accepted_drift` value and needs
an orchestrator status update.
