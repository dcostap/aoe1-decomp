Current source: `src/sprite.cpp`. This ledger contains historical review evidence.

## Phase transition

The main agent suspended ordinary exact matching on 2026-08-02 after repeated
independent assignments and more than one hundred documented source, liveness,

exhausted the remaining branch-point parameter-load and assignment-in-condition

### Semantic questions at entry

Blind reviewers must establish these directly from the executable rather than
trusting the source or this ledger:

1. Exact signedness and conversion behavior of `delta_time`, `param_1`, the
   elapsed subtraction, and the `180000` threshold comparison.
2. Behavior when `loaded` is zero, `shape` is null, or `delta_time` is zero,
   including which fields are read or written before each return.
3. Exact order and widths of writes to `last_time`, `delta_time`, and `shape` on
   every reachable path.
4. Exact destructor and deallocation calls, arguments, null checks, and whether
   `shape` is cleared after destruction in every applicable path.
5. Whether NaN or floating-point environment details can matter despite the x87
   operand originating from an integer conversion and comparison with zero.
6. Any aliasing or wraparound edge case caused by the timestamp subtraction and
   signed/unsigned conversions.

#### Reviewer 1 — broad adversarial behavior

> **Overall conclusion:** No definite behavioral difference found for valid
> objects under ordinary single-threaded execution. The candidate reconstructs
> all reachable paths and side effects correctly. Remaining mismatch is
> code-generation, not evident logic drift.
>
> **Verified against original evidence**
>
> - `loaded == 0` exits without touching timing or shape state
>   (`004C1086–004C108B`).
> - Null `shape` exits (`004C108D–004C1092`).
> - `delta_time == 0` uses signed 32-bit FPU comparison against the double-zero
>   global (`004C1094–004C10A7`), then stores `last_time = param_1` and
>   `delta_time = 1`.
> - The nonzero path performs 32-bit wrapped `param - last_time + delta_time`,
>   stores `last_time` before `delta_time`, and uses a signed comparison against
>   `180000` (`004C10C1–004C10D7`).
> - The threshold path calls `TShape::~TShape` with the saved shape pointer
>   (`004C10DD`, target `004B8DD0`), then the cdecl delete wrapper
>   (`004C10E4`, target `0054B660`, which calls `free`), and finally clears
>   `shape` (`004C10ED`).
> - Return is void with `ret 4`; the candidate matches this behavior.
>
> **Plausible concerns**
>
> 1. The candidate reloads `this->shape` into `pS2` before deletion, whereas the
>    original uses the pointer saved at `004C108D`. With normal non-concurrent
>    execution they are identical because no intervening call changes the field.
>    Under unsynchronized concurrent mutation, the candidate could delete or
>    skip a different pointer. This is not a defined ordinary C++ execution.
> 2. The original performs machine-level 32-bit wrapping arithmetic. The
>    candidate's signed expressions can technically invoke signed-overflow or
>    implementation-defined conversion rules in portable C++, although VC5's
>    generated integer operations preserve the original bit behavior.
> 3. The volatile parameter read changes source-level access ordering but cannot
>    affect the value in normal execution because the parameter address does not
>    escape.
>
> No null-path, cleanup, ownership, FPU predicate, width, threshold, or
> return-value discrepancy was established.

>   the initial `pS` only for the guard, then reloads `this->shape` into `pS2`
>   before deletion. In ordinary single-threaded execution there is no
>   intervening callback, so both values are the same. Under an asynchronous
>   writer, signal handler, or other external alias mutation, behavior differs:
>   the candidate may delete the newer pointer, while the original deletes the
>   original snapshot.
>
> **Verified equivalent behavior**

> - `loaded` is byte-sized at `+0x14`; `shape`, `last_time`, and `delta_time` are

>   `>= 180000` threshold.

>   `operator_delete(shape)`, then clear `shape`; call arguments match.

>   `ret 4`, and the return type is `void`.
>
> **Plausible concerns / unestablished areas**
>
> - `last_time` is modeled unsigned rather than the reference's signed `long`,
>   but immediate conversion to 32-bit `int` preserves observed arithmetic.
> - Signed overflow is nonportable, while pinned VC5 preserves the executable's
>   wraparound behavior.
> - The local `TShape` declaration omits fields, but this caller does not access
>   them.
> - Exact rebuilt x87 status-word side effects and external symbol binding were
>   not independently checked by this read-only review.
>
> **Conclusion:** No ordinary single-threaded behavioral discrepancy was found.
> The only meaningful semantic issue is the candidate's second `shape` load;
> using the original cached pointer would be safer for exact
> aliasing/asynchronous behavior.

## Main-agent adjudication

### Formal round 1 adjudication

- **Cleared — second `shape` load under the supported execution model.** Both
  reviewers independently noticed that the candidate reloads `shape`, while the
  original retains the entry snapshot in `EDI`. There is no call, escaped local,
  or source-visible mutation between the first and second load. A competing
  unsynchronized writer would be a C++ data race; an asynchronous signal handler
  mutating this non-volatile object would likewise not provide a defined C++
  execution whose behavior this reconstruction must preserve. The rebuilt
  artifact also retains the original cached pointer in `EDI` for the actual
  destructor and delete calls. This source-level reload therefore does not leave
  an open behavioral finding for the pinned game execution model.
- **Cleared — 32-bit overflow and signedness.** The original instructions prove
  modulo-32-bit subtraction/addition followed by a signed threshold compare.
  The pinned VC5 artifact emits those same machine-width operations; modern C++
  portability is not the oracle.
- **Cleared — FPU and relocation uncertainty.** Main-agent validation confirms
  the rebuilt call targets are ordered and aligned, and the candidate's integer
  to double zero predicate has the same truth value for every 32-bit integer.
  The original qword is the established zero global `DAT_00574528`.
- **Cleared — ABI, accesses, paths, and lifetime.** The two reviews agree with
  the packet evidence on all field offsets and widths, guard paths, stores,
  signed threshold, destructor/delete arguments and order, clearing of `shape`,
  and void `ret 4` behavior.

Formal round 1 leaves no substantive finding open. It supplies the first complete
concurrent cohort required by the current workflow; another fresh formal cohort
is still required before final promotion because the standard requires repeated
independent convergence.

### Formal round 2 adjudication

- **Cleared — apparent second `shape` read.** The concern was independently
  rediscovered by both round-2 reviewers. Main-agent full-range rebuilt
  disassembly proves VC5 eliminates the source-level reload: rebuilt B005 tests
  the same `EDI` snapshot loaded in B001, and rebuilt B006 passes that `EDI` to
  both the destructor and delete calls, exactly like the original. Thus even the
  emitted candidate behavior snapshots one pointer; no concurrent/asynchronous
  counterexample exists at machine-code level.
- **Cleared — extreme arithmetic.** Rebuilt B004 uses 32-bit `sub` and `add` and
  then a signed `cmp`/`jl`, so every input bit pattern has the original modulo-
  32-bit arithmetic and signed threshold behavior. Portable-language undefined
  behavior is not substituted for the actual pinned VC5 artifact.
- **Cleared — volatile parameter ordering.** Rebuilt B002 loads the unescaped
  by-value parameter before the x87 comparison whereas the original loads it
  immediately after the status test. Neither instruction can fault for a valid
  frame, the stack home is unaliased and unescaped, and the x87 sequence does not
  access it. The movement cannot alter any observable game state or x87 result.
- **Cleared — x87, symbols, ABI, and lifetime.** The integer conversion cannot
  be unordered; checker validation confirms both direct call targets are ordered
  and aligned; and full-range disassembly confirms the expected argument
  registers/stack cleanup, nulling store, and return convention.

Formal round 2 independently converges with the pilot and formal round 1: no
substantive behavioral finding remains open. The repeatedly raised concerns are
resolved against the emitted candidate artifact and supported execution model,
not by reviewer vote.

## Final decision

Approved for `verified_logic` status on 2026-08-02 after one blind pilot review and
two complete fresh concurrent blind cohorts (five independent reviews total),
followed by main-agent instruction-level adjudication. The cohorts repeatedly
converged on the same three caveats—source-level `shape` reread, signed-overflow
portability, and parameter-load timing—and emitted-code evidence clears each one:
the rebuilt artifact uses the cached shape pointer, performs the same wrapping
32-bit arithmetic and signed threshold comparison, and only moves an unescaped
parameter-home read across a side-effect-free integer-to-double zero test.

All reachable guards, field widths and offsets, mutation order, arithmetic,
threshold behavior, destructor/delete arguments and ordering, nulling store,
call conventions, and returns are accounted for. No substantive semantic
finding remains open.

The remaining nonsemantic drift is the validated entry-state compiler scheduling
and register-allocation mismatch: original/rebuilt size 123/123, frame none,
saved registers aligned, calls 2/2 ordered and target-aligned, CFG conditional
branches 5/5 and returns 2/2, strict difference 71 bytes in 12 spans, and bounded
edit cost 14.63%. Promotion is a semantic reconstruction claim only and does not
assert exact machine-code parity.
