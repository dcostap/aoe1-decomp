## Behavior

Static review supports the worker's main algorithm claim. The source and oracle
both:

- log the world time, player ID, action `1`, input ID, coordinates, radius,
  square mode, and suppression value;
- return `0` after the log when `Map_Update_Suppresion != 0`;
- update `input_csum` with the rotate/XOR sequence and the player ID;
- read the current player after the checksum store and guard a null current
  player before `mutualAlly` access;
- clamp only a radius above `0x10` and select `SquareLOS` or `NormalLOS`;
- clip rows and columns, read the unified row before the visible row, update
  explored and visible masks, update counters and tile lists, write `draw_as`
  only when `UpdateMap != 0`, convert `0xFA` to `0xF9`, and advance all cursors;
- call `RGE_Tile_List::add_node` at the two oracle sites.

The missing-tile conclusion in the worker evidence is wrong. The PDB packet
supports `tile` as an `RGE_Tile*` at `+0x10`. It also places `radius` at
`+0x10`, proving a reused formal/local home. More importantly, the oracle at
`0053C7BC` executes `mov [ebp+10h],ecx` after `ecx` is zero. The Ghidra packet
also shows `param_3 = 0` before radius clamping. This is the initialization of
the reused `tile` home. Therefore the current `RGE_Tile* tile;` source does not
preserve the oracle value. The tile-init child is a valid behavior and source
repair lead, not an invalid-path pointer-arithmetic preservation.

The zero value has no tile dereference when `UpdateMap == 0`, but the oracle
still initializes and increments that reused home. When `UpdateMap != 0`, the
map row assigns the tile cursor before any draw store. This is a proven machine
state and source fact. It also removes the current source's uninitialized
pointer use. The tile-init edit is natural and is supported independently of
its byte result.

No runtime harness exists for this method. The following remain untested:
null or malformed `this`, world, player, map, row, unified-map, and LOS
pointers; invalid `curr_player`; out-of-range player IDs; negative dimensions;
integer overflow in coordinate and counter arithmetic; malformed LOS
terminators; reentrant or concurrent mutation of `this->player`; and exception
or fault order. The unscoped player alias probe is correctly rejected because
it reads `this->player` before the oracle's current-player lookup. The scoped
alias retains the non-null guard and is byte-neutral, but it does not establish
complete fault or concurrency equivalence.
