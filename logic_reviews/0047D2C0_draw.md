`src/scratch/0047D2C0_draw.cpp`.

Current validated checker state:

The executable keeps the vtable/top-line value in `EBX` and the DC in `EDI`.

forms converged on the same register-color group.

The retained source uses named panel fields, typed GDI calls, ordinary line
iteration, and natural draw setup and cleanup. It contains no fake volatility,
manual vtable calls, raw offsets, or codegen-only control flow.

## Review rounds

### Round 1 — concurrent blind cohort, 2026-08-12

- `sa-78e02534` — `openai-codex-secondary/gpt-5.6-luna`, xhigh
- `sa-591cc733` — `deepseek/deepseek-v4-flash`, high

#### Luna report

Verified behavior:

- `need_redraw` reset and the render-area, visible, and active guards match.
- Every early exit skips all drawing calls.
- Background, setup, DC acquisition, clip/font/background calls, line drawing,
  font restore, clip clear, DC release, border, and finish calls match in order.
- A zero DC still calls border and finish.
- Highlight colors and normal colors use the proven fields and predicate.
- `bot_line` is reloaded after each `draw_line`, allowing helper-side changes.
- Both line arguments are consumed as signed 16-bit values.
- GDI failures are not checked. There is no RAII cleanup after a fault.
- The original does not restore background mode and clears rather than restores
  the prior clip region; the source preserves these effects.

Concerns:

1. The executable loads `render_area` at `0047D2C9` before storing
   `need_redraw=0` at `0047D2CC`; the source statement order is assignment then
   guard. A malformed object fault could distinguish abstract source order.
2. Signed-short increments can wrap and produce a nonterminating loop when
   `bot_line==32767`; C++ signed overflow is undefined.
3. The executable snapshots the vtable at `0047D2F0` and uses it for finish.
   Source virtual-call syntax does not explicitly preserve this if a prior call
   corrupts the vptr.

Conclusion: no normal-path difference. Fault order and short overflow required
main-agent adjudication.

#### DeepSeek report

The reviewer verified the raw EXE, IAT bindings, string address, and downstream
line consumers.

Verified behavior:

- Guards and shared early epilogue match.
- All 12 direct, virtual, and GDI call sites match in order and arguments.
- Highlight short-circuit logic and color order match.
- The loop uses signed 16-bit line comparisons and reloads `bot_line` each time.
- The original's 32-bit line-index counter and stale high bits are unobservable:
  downstream consumers read the low signed 16 bits.
- Cleanup and the zero-DC path match.
- Invalid handles are passed through identically.

Examined concerns:

1. Short wrap produces the same low 16-bit behavior and possible nontermination.
2. Stale high bits in the original pushed line value are ignored by consumers.
3. Vtable snapshot versus source virtual-call spelling was judged equivalent for
   a valid object with no vptr write.

Findings: no definite difference. Conclusion: complete semantic equivalence;
the 18 bytes are register coloring only.

## Main-agent adjudication

- **Guards, calls, loop predicate, color logic, cleanup, fields, and ABI:**
  confirmed by both independent traces.
- **Initial read/store order:** cleared for the pinned candidate. The current VC5
  object emits the executable order: load `render_area`, then store
  `need_redraw`. The source has no defined malformed-`this` behavior that the
  executable order would contradict. Adding a codegen-only preload would reduce
  source plausibility without changing the validated machine behavior.
- **Short overflow:** cleared under the pinned VC5 execution model. The emitted
  16-bit increment and signed compare match. DeepSeek also proved every consumer
  reads only the low signed 16 bits of line and line index.
- **Saved vtable:** cleared for valid C++ object lifetime. No candidate statement
  changes dynamic type or starts destruction. The current emitted object also
  snapshots and reuses the vtable exactly as the executable does.

Round 1 found no substantive open behavior issue. No source change is justified.
A second fresh cohort is required before final promotion.
