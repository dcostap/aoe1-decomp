### Access-order limitation

The original positive horizontal arm reads `tab_min_x` at `0047B1D7`, reads
`tab_x` at `0047B1DD`, and reads `tab_min_x` again at `0047B1E3`. The clean
rebuild reads `tab_x` first at `0047B1D7`, then reads `tab_min_x` at
`0047B1DD`, and retains that value for the lower clamp. The vertical arm has
the same pattern at `0047B2B5`, `0047B2BB`, and `0047B2C1` versus the rebuild's
current-first sequence.

The task-list pointer and vtable reads keep the same order in both bodies.
Some stack-argument loads interleave differently with member and address
loads. The limitation is therefore not a claim that the task-list or vtable
read order changed. It is a limit on fault-order equivalence for the edge and
stack reads.

The two sequences can fault in a different order for a damaged object. They
can also observe a different value if another actor changes a field between
reads. The available evidence does not prove equal memory effects or fault
order. This is a blocker for accepted drift. It is not a reason to add an
unsupported local or wrapper to the clean source.
