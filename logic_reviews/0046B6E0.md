## Radius calculations

Original `0046BD46..0046BE32` reloads the current object and master after the earlier setup work.
It then loads X radius once and copies Y radius bits into a float local.
The old source retained the earlier master pointer and repeatedly read radius fields.

The repair uses `xRadius` and PDB-supported `yRadius` locals.
It computes the four primary deltas before the four scaled deltas, as the original does.
It retains the original cached edge values instead of evaluating their expressions again.

The generated floating-point sequence agrees with the original:

- The X radius and X edge remain on the x87 stack across conversions.
- The minimum edges receive the same 32-bit stores and later loads.
- The Y radius receives an integer bit copy, not an early floating-point load.
- The Y edge receives the same 32-bit rounding store before later reuse.
- All eight conversions occur in the original order.
- Loads, additions, subtractions, multiplication, and x87 stack operations retain their order.

The private homes change from `+8/+1C/+3C` to `+1C/+3C/+40` for Y radius and the minimum edges.
The review applies the approved private-workspace input scope. It does not exclude ordinary caller-owned stack objects.
No assembly, volatility, artificial layout, or compiler control forces these results.

The earlier metric-based rejection of a named radius does not reject this repair.
The executable and PDB support the source, and the emitted arithmetic confirms it.
