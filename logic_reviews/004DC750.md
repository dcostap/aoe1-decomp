# 004DC750 objectToAttack: ordered score repair

## Decision

Approve the ordered integer score additions as a partial source repair.
Keep the function in `scratch`. This review does not establish whole-function equality.
The shared protected-array proposal remains separate.

## Original evidence

Original `004DCCE9..004DCE5B` contains 85 score instructions and 14 getter calls.
The executable calls `TribeTacticalAIModule::strategicNumber` in this order:

`59, 90, 7B, 7A, 50, 53, 4D, 6F, 5A, 4E, 4F, 52, 6E, 6D`.

Each number above is hexadecimal.
The executable multiplies each returned integer by its term and accumulates the results in that order.
It reloads the main-module pointer before each getter call.

Original `004F6210` performs a read-only, signed bounds check and integer lookup.
It accepts indices from zero through `0xE1`. It returns `-1` outside that range.
Call counts alone cannot establish the required indices, pointer reads, or accumulation order.

## Repair

The previous long sum left operand evaluation order unspecified.
Its getter order changed with the compiler inputs, including the protected-array proposal.
Initialize `rating` with the first product. Use one `rating += ...` statement for each remaining product.

The rebuilt score region is `004DCCFD..004DCE6F`.
All 85 operations agree with the original after direct-target resolution and two private-home mappings:

| Value | Original stack offset | Rebuilt stack offset |
| --- | --- | --- |
| `specialRating2` | `0x3C` | `0x40` |
| `typeMatchB` | `0x40` | `0x64` |

The earlier assignments identify those homes. The mapping does not merge distinct values or change their widths.
The comparison preserves every pointer read, push, multiply, addition, and register operation in this region.
It checks all 14 call relocations against the owning getter symbol.
It does not mask other instruction differences.

The machine operations retain the original low 32-bit multiplication and addition results.
The region introduces no floating-point operation, allocation, write through a caller pointer, or exception handler.
It restores the original order for pointer-read faults and getter calls.
Caller-owned overlap remains in scope. Fabricated pointers into future private stack storage do not.

## Limits

This repair does not approve the complete function, its layouts, or all earlier arithmetic and fault paths.
The complete result remains `MISMATCH`:

- Original: 1,977 bytes. Rebuilt: 2,008 bytes.
- Positional differences: 1,419, or `70.6673%`.
- Both frames: `0x88`. Both bodies save `EBX`, `EBP`, `ESI`, and `EDI`.
- All 44 calls align. The owner symbol agrees.

The main and protected builds now emit identical descriptions for this complete owner.
That agreement resolves this owner's shared-header difference. It does not replace comparison with the executable.

## Closure

The protected score-only probe changes one owner among 141 information-module emissions.
The main patch also includes the independent resource-membership change reviewed in `logic_reviews/004D9240.md`.
Together, those changes affect two owners among 140 main information-module emissions.
All 98 matching targets pass with either header.
No registry, header, flag, or other source module changes on main.

The protected information module still differs in `004DE600 checkDefend` and three helper descriptions.
Those differences are not approved by this review.
