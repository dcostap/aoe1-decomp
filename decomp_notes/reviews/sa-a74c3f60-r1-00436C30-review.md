## Behavior

The current source preserves the binary-supported operation order:

- It publishes `world` before the null guard.
- It reads and publishes the map dimensions with short-width fields.
- It frees old tile rows before `calloc`.
- It computes the row step and projects each image line.
- It stores `tile_row` in the image-line record before row-table stores.
- It preserves the row-table field writes and the second-pass source-row rule.
- It resets `view_col` and `view_row`, then calls immediate redraw.
- It clears `map` on the failed world or image-line guard path.

The original body is 282 instructions. The rebuilt body is 279 instructions.
Both bodies have the same frame, saved registers, control-flow counts, and seven ordered call sites.

The first strict difference is offset `+0x14F` (`00436D7F`).
The oracle loads row length before line length and duplicates the quotient on x87.
It stores the quotient to the `col_step` home without popping it.
It then divides the original `1.0f` value by the extended quotient.

The rebuilt code spills the quotient to a 32-bit float home with `fstp`.
It reloads that rounded value before the reciprocal division.
This changes the x87 value used by later conversion and field stores.
It can change `__ftol`, draw width, ratios, and later map geometry.
Therefore, semantic equivalence is not proved.
