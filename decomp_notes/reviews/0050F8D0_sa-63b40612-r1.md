## Behavior

The packet, dossier, and original listing assign the target to
`TRIBE_Map::check_tile_for_forest_change` in `tmap.cpp`. The ABI is `__thiscall`
with `short x`, `short y`, and `RGE_Game_World* world`. The PDB binds `this` to
`TRIBE_Map*` in `ecx`.

The original reads the center tile before the bound clamps. It reads the row
table at `TRIBE_Map` offset `+0x8D8C`, uses a `0x18`-byte tile stride, and
reads terrain at tile byte `+5`. It clamps the `short` neighborhood against map
width `+0x8` and height `+0xC`.

For center terrain `0x0A`, the source scans rows and cells in row-major order.
It marks the change when a scanned terrain is neither `0x0A` nor `0x12`. It
then calls `change_terrain(x, y, 0x12, world)` when marked.

For center terrain `0x12`, the source walks the tile object list at `+0x10`.
It tests the master object's `object_group` at `+0x14` and the object state at
`+0x48`. It does not stop after a match. When no live forest object exists, it
calls `change_terrain(x, y, 0, world)` first. It then visits the bounded
neighborhood in row-major order and recurses for every non-center cell.

The original and source preserve the important row-load and fault order:

1. The center load is `map_row_offset[y] + x`, before clamps.
2. The forest scan seeds the current row from `map_row_offset[y0] + x0`.
3. The scan advances each cell by one typed `RGE_Tile` (`0x18` bytes).
4. After each row, it reads the next row slot and then advances the row-table
   cursor by four bytes. This includes the post-final-row read.
5. A row or cell guard does not remove the preceding row or tile load.

The source uses `RGE_Tile** row_cursor` for row-table ownership and
`RGE_Tile* row_tile` for tile ownership. These types match `include/map.h` and
the original pointer operations. No runtime harness was supplied. Null,
malformed-table, overflow, allocation, exception, and complete fault-path
behavior remain untested.
