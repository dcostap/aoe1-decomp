## Behavior

- The original body spans `0048D0E0-0048D4C2`, or 995 bytes.
- It counts `.scn` files, then `.scx` files. The signed 32-bit total sizes the new array.
- A nonpositive total returns without changing the old array.
- It starts with `.scn` files. If that search fails, it starts `.scx` and sets `looped`.
- If the later `.scn` search and `.scx` fallback both fail, it returns without freeing the old array.
- After a `.scn` pass, it searches `.scx` once. It does not close search handles.
- This is a confirmed resource leak. The wrappers call `FindFirstFileA` and `FindNextFileA`, then omit `FindClose`.
- See `inventory/functions/0054/0054C2A0_findfirst.txt` and `inventory/functions/0054/0054C3D0_findnext.txt`.
- It compares names with case-sensitive `strcmp`, then stops at the first matching old entry.
- It reuses an old entry when `file_info.time_write <= old.time`. Equality also reuses the header.
- A newer file gets a copied name and modification time. The code then opens its path.
- On open success, it reads four bytes into `version`, calls the `+0x38` virtual slot, then closes the file.
- Path formatting, open, read, header creation, pointer store, and close keep this order.
- An earlier fault skips later calls. The function has no cleanup handler for that path.
- Open failure leaves the zeroed header pointer null. The code does not check `calloc` failure.
- Final cleanup deletes each remaining old header, frees the old array, then stores the new pointer and count.
- The count and enumeration use signed 32-bit values. The loop index is also signed.
- The source keeps unbounded `sprintf`, stale counts, and early-return behavior.
- The source keeps allocation failure, changing-directory, and malformed-name behavior encoded by the binary.
- I did not run a scenario fixture or a runtime edge-case test.

### Stack-adjustment correction

An early hypothesis changed the stored time to `file_info.size`. That hypothesis was wrong.

At `0048D367`, the original pushes one temporary argument. At `0048D371`, `[esp+138h]` therefore addresses `file_info.time_write`, not `size`.

The field layout is in `inventory/types/dumps/finddata_t.txt`. The wrapper writes `time_write` at offset `+0x0C`.

The experiment increased the byte difference from 10 to 11. State `fe28d856493c6cebf5788d9a9348d31e633dae420a62ae9c7f2fa03b79714f9a` records it.

Finding event `f14b59817e1b73497c2517e1265bea78bfc1d9610aa7084e5c84d38f495d50b2` rejects that hypothesis.
