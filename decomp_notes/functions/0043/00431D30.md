# Function notes: 00431D30 `GetSpecificItem`

## Root integration decision

The source now keeps saved EDI live through the `Size` output write.
The old source restored EDI too soon for an output alias to its stack slot.
The repaired body exceeds the original boundary by two bytes.
The root changed this target to `scratch` pending a boundary-safe form.

## Behavior

The original body has 156 bytes, from `00431D30` through `00431DCB`. It uses `__thiscall` and makes no calls.

The queue pointer is at `this+0x114`. `HighQueueDepth` is at `this+4`.
The `MsgQueue` record is `0x1C` bytes. Its field offsets are:

- `Code`: `+0x00`; `ExecTurn`: `+0x04`; `SeqNo`: `+0x08`.
- `msgptr`: `+0x0C`; `From`: `+0x10`; `Size`: `+0x14`; `ControlCommand`: `+0x18`.

The function masks `Seq` to eight bits. It computes `FromPlayer * 1000 + Seq` with 32-bit unsigned wrap.
The stack arguments are `FromPlayer` at entry `ESP+4`, `ExecuteOnTurn` at `ESP+8`, `Seq` at `ESP+0xC`, and `Size` at `ESP+0x10`.
It reads `Queue` once before the scan. It compares `Code` first, then `ExecTurn` after a code match.
After each failed pair, it increments the index and record pointer. It then repeats while `index <= HighQueueDepth`.
The scan visits indexes `0` through `HighQueueDepth`, inclusive. It does not test `Size`.

If no record matches, the function returns null. It does not write through `Size`, change a record, or update `retptr`.
A zero `Code` and zero `ExecTurn` can match an empty record when the requested code and turn are also zero.
A `HighQueueDepth` of zero still checks one record. A value of `0xFFFFFFFF` can wrap the index and keep a miss loop running.

On a match, the function reads the record `Size`, then writes four bytes through the caller's `Size` pointer.
It reloads `this->Queue`, reads `msgptr`, and stores that pointer in static `retptr`.
It reloads `this->Queue` again and clears `msgptr`.
It reloads `this->Queue` again and clears `Code`, `ExecTurn`, `SeqNo`, `From`, `Size`, and `ControlCommand`.
`SeqNo` is one byte. The other cleared fields are four bytes. The record padding stays unchanged.
The function finally reloads and returns `retptr`. It returns with `ret 10h`.

A null `Size` pointer faults only after a record matches. The record `Size` read occurs before that fault.
The output write occurs before the `msgptr` read and before every queue-field clear.
If `Size` aliases `this->Queue`, later queue-base reloads observe the changed pointer.
Do not replace those reloads with a cached pointer after the output write.

The original writes `*Size` at `00431D8B`. It restores EDI at `00431DC5`.
A `Size` pointer aimed at the saved EDI slot can change the value restored to the caller.
Baseline rebuilt code pops EDI at relative `+0x4B`, before its output write at `+0x5C`.
That changes the saved-EDI alias result. This is an ABI-level counterexample to full behavior equivalence.
No direct source caller of this method was found. Runtime tests were not run.
