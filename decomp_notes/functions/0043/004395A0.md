### Machine-effect review after root rejection

The earlier drift note was incomplete. This section gives the block proof for
the current natural source and does not claim exact code generation.

- Entry and call setup: both paths reserve 0x14 bytes and pass `dib`, then
  writable width, height, and orientation addresses to `GetDibDim`. The
  different `EBX` save point changes only private stack slots. Stack slots are
  valid under the entry ABI and no user pointer is read in this block.
- Dimension and allocation block: both read the height result, then read
  `dib->bmiHeader.biWidth`, store the raw width in a private home, compute
  `height << 4`, and call the same `malloc` target. Both read `info` and store
  the returned pointer to `info + 0x14` before testing it. Thus an invalid
  `dib` faults in `GetDibDim`, an invalid `info` faults at that same first
  field store, and allocation failure returns 1 without a scan.
- Allocation-failure exit: both return 1 and restore the caller's saved
  registers. The rebuilt path saves `EBX` later, but it does not change `EBX`
  before this exit. No external read or write differs.
- Height guard: both initialize `tw` and the row counter to zero, then test
  the normalized height. The extra rebuilt save and the delayed original
  save touch only the valid private stack area. A non-positive height reaches
  the common final block with no bitmap read and no line-record write.
- Row setup: each loop iteration selects `width * y` when orientation is 1,
  otherwise `(height - y - 1) * width`. Both read the bits argument only
  after this arithmetic and form the same `bits + row` base. Register and
  `LEA` differences do not change the address or fault point.
- First scan: both skip the scan when raw width is non-positive. Otherwise,
  each iteration reads exactly `bits[row + x]`, tests it for zero, and then
  either sets `tw` once for the first zero or clears `all_trans` and records
  the first nonzero index. Both increment `x` and continue while `x <
  raw_width`. The first invalid bitmap-byte fault is therefore identical.
- Last-index scan: both enter only when `all_trans` is false. Both set
  `x = first + 1`, check `x < raw_width` before any read, read the same byte
  sequence, update `last` only for nonzero bytes, and increment `x`. No call
  or external write occurs in this block.
- Solid scan: both enter only when `all_trans` is false. Both set `solid = 1`,
  start at `first`, check `x <= last`, and read the same bytes. The first zero
  writes `solid = 0` to a private value and exits. A bitmap fault occurs at
  the same byte and before any line-record write in both paths.
- Line record stores: both calculate record `y * 0x10` and write offsets 0,
  4, 8, and 0xC in that order. Each path reloads `info->LineInfo` before each
  write. If `info` or `info->LineInfo` is invalid, both fault at the same
  first field read or first store. The different register and cursor values
  represent the same record address and values.
- Row boundary: both increment the row counter, compare it with height, and
  repeat for the same rows. The loop has no call and no external effect other
  than the four ordered record stores.
- Final block: both read the private `tw` and the `info` argument, although
  the rebuilt code reverses those two stack reads. These are reads from the
  active stack frame, not pointer dereferences. Under the entry ABI, neither
  can fault before the other. Both then test `tw` and store the same value to
  `info->AnyTrans` at offset 0. An invalid `info` faults at this store after
  the same completed row work.
- Free path and return: when `tw` is zero, both read `info->LineInfo`, pass
  that identical value to the same `free` target, and perform no later field
  access. A fault inside `free` has the same target and argument. When `tw`
  is nonzero, neither calls `free`. Both return `tw` and restore all
  callee-saved registers.

Alias review: `dib`, `info`, and `bits` may alias each other. The external
access sequence remains the same in both paths: `GetDibDim` reads the bitmap,
the allocation result is published, bitmap bytes are read, four line fields
are written, and `AnyTrans` is written before the optional free. A line buffer
that aliases an input therefore receives the same writes at the same loop
boundary before any later read. A bitmap or bits pointer that aliases `info`
also sees the same publication and row-store order. The private stack homes
cannot overlap valid incoming argument storage because they are below the
entry stack pointer.

Fault review: integer adds, subtracts, shifts, compares, branches, and address
calculations do not fault on this x86 target. The only external memory reads
are the `GetDibDim` bitmap reads, the scan-byte reads, and `info` field reads.
The only external writes are the published line pointer, four line fields per
row, and `AnyTrans`. Each pair has the same predecessor operations and the
same logical address. Invalid `dib`, `bits`, or `info` pointers therefore
fault at the same logical access, including every alias case.

This proves equal defined machine effects and external-pointer fault order
under the x86 entry ABI. It does not prove stack-page faults after corrupted
entry state, allocator internals, or byte identity. The proposal remains
accepted drift only if root accepts this scope.

### Root decision

Root rejected accepted drift. The broad register-allocation gap gives different
register state at invalid-pointer faults. An exception handler can inspect that
state. The proof covers effect and fault order, but it does not prove equal
exception behavior. The function remains `scratch`.
