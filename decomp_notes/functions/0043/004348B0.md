## Worker pool20-37-command-004348B0 validation

The fresh natural-TU baseline and final check remain `MISMATCH`, 5 strict
bytes (9.4340%), with 53/53 bytes, 23/23 instructions, no frame, one aligned
virtual call, matching ownership, boundary, relocations, and vslot `+0x18`.

The complete five-byte span is a register/load-order swap. The original starts
with `mov eax,[esp+4]` then `mov ecx,[ecx+4]`; the rebuild starts with
`mov ecx,[ecx+4]` then `mov eax,[esp+4]`. Both sequences resynchronize at
`+0x6`; every later instruction and byte is equal. The original therefore
reads the `order` stack home before reading `this->world`. The rebuild reads
`this->world` first. This can change the first fault for invalid `this` or an
unreadable parameter home, so the difference is not accepted drift.

The PDB scoped record proves `order` at stack `+0x4` with type
`RGE_Command_Create*` and `this` in `ecx` with type `RGE_Command*`. Assembly
proves `order->player_id` at `+0x4`, signed `order->obj_catagory` at `+0x2`,
and coordinates at `+0x8`, `+0xC`, and `+0x10`. The typed source resolves
`world->players[player_id]`, then `player->master_objects[obj_catagory]`, and
calls `make_new_obj(player, x, y, z)` through vslot `+0x18`. ABI, values,
aliases, effects, call target, argument order, and later fault order match.

The one-job Command audit is in
