## Runtime repair

### Behavior

The old source passed the object ID twice to `TRIBE_World::check_destructables`.
During random-map placement, object ID 109 became the player-array index.
The resulting pointer was `FFFFFFFF`; the callee faulted while reading its master-object array.

Original `00512F98` loads a short from player offset `4A`.
Original `00512FA1` pushes that member as the first argument.
The second argument comes from the object-ID parameter at `00512F94` and `00512FA0`.
The PDB layout identifies player offset `4A` as `short id`.

The complete function forwards object ID, x, y, z, and the creation flag to the base creator.
A null result skips all object accesses and returns null.
A nonzero creation flag checks destructables with player ID, object ID, x, y, and zero.
It builds type `0x50` objects with `10000.0f`.
Editor mode seven sets frame five for groups five and `0x21`.
The original call order, receivers, field accesses, and return value remain intact.

### Source

Use `this->id` to distinguish the player member from the object-ID parameter.
Use the original positive object guard and common return.
The prior accepted-drift label covered a real argument defect and was incorrect.
Runtime evidence justifies reopening that result.
