## Behavior

The original body is `00504750-00504875` (294 bytes), with `__thiscall` ABI.
PDB symbols place `nEvent` at entry `+4`, `uTime` at `+8`, and `this` in ECX.
Both parameters are 32-bit. The function has no listed static data.

The function reads `nEvent->mType` first. Types other than `0x200` call the
base `UnitAIModule::processNotify` with both parameters and return its result.
For type `0x200`, actions other than `600` return `2`.

The `600` path reads `currentTargetValue` before it dereferences
`objectValue->owner->world`, then calls `RGE_Game_World::object`. A null target
returns `2`. The target's virtual `getSpeed` call uses vtable slot `+0xF4`.
The original compares its result with the zero value at `005758C4`. Equal and
unordered x87 comparisons return `2`; other values continue.

The function then calls `order` through slot `+0x10`. Its arguments are the
unit ID, order `0x2BC`, current target, owner `-1`, current target XYZ, desired
distance, `immediate=0`, `inFront=1`, and current priority. The reviewed
`UnitAIModule::order` implementation queues this order when object state is at
most `2`; the caller ignores its return value.

Next, the function calls `rateOfFire` (`+0x100`) and `maximumSpeed` (`+0xFC`),
then scales their product by `3.0f` from `005758B0`. It computes target-minus-
self X and Y deltas, their squared sum, and a float square root. It divides
each delta by that distance, multiplies by the scaled speed, negates with
`FCHS`, and adds the matching self coordinate with `FADD`. It loads self Z
after the squared deltas and before the square root. It passes X, Y, Z, and `1`
to `evasiveMoveTo` through slot `+0x9C`, then returns `3`.

There is no zero-distance guard. Preserve the division and the call for equal
positions. No runtime game test was available. This review uses the original
executable listing, PDB symbols, local method bodies, and rebuilt code.
