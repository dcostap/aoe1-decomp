# 00478730: list keyboard dispatch repair

## Behavior

Original instructions dispatch through a byte selector at `00478828` and pointer table at `00478808`.
The input index is key minus `0x0D`; values above `0x1B` take the default return.
Reading both tables from the original PE gives these targets:

| Key | Original target | Scroll action |
| --- | --- | --- |
| Enter (`0D`) | `004787C8` | Parent action 3, only for a valid selected line |
| Page Up (`21`) | `0047878C` | 5 |
| Page Down (`22`) | `00478778` | 4 |
| End (`23`) | `004787B4` | 7 |
| Home (`24`) | `004787A0` | 6 |
| Up (`26`) | `00478764` | 3 |
| Down (`28`) | `00478750` | 2 |

Each scroll call passes line 0 and flag 1. Each handled key returns 1.
Other keys return 0. Enter checks the parent and the signed selected-line bounds before calling it.
These instruction paths remain unchanged.

The old source assigned actions 4, 5, 6, and 7 to End, Home, Page Up, and Page Down respectively.
That contradicted the original table, despite matching local function bytes.
The correction changes those four case labels in `src/pnl_lst.cpp`.
The adjacent `TTextPanel::key_down_action` uses the same corrected key/action mapping.
