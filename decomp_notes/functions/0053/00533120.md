# Function note: `00533120` `handle_points_attribute_amount`

Module note: `decomp_notes/victory.md`.

## Behavior

A nonzero entry state returns before reads or writes (`00533128-0053312D`). For state 0, the function loads the player's attribute and calls `__ftol` (`0053312F-00533140`). It sign-extends the integer result for signed division by `node->amount`. The division occurs before the current-attribute store (`00533144-0053314C`), so divide-by-zero and signed divide overflow fault before that store.

It clamps a negative quotient to zero, multiplies by signed `points`, and compares with `curr_points` (`0053314F-00533160`). Only a changed result updates total points and `curr_points` (`00533162-0053316E`). The code uses 32-bit arithmetic. Runtime tests and divide-fault injection were not run.

## Source

VC5 `int` and `long` are both signed 32-bit here, so the change does not alter emitted code. `calculated_points` remains an `int`, matching the quotient's dword operations.
