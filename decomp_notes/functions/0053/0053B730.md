# 0053B730 — Build_Distance_Table

## Decision

Keep the bounded `for` loop in `src/vis_unit.cpp`. It walks `NormalLOS[0]` through `NormalLOS[16]`. This is the simplest tested source form.

The original function is 173 bytes. The rebuilt function is also 173 bytes. The source compiles under the pinned VC5 profile. The byte check still reports 10 differing bytes. Do not tune bytes without new behavior evidence.

## Behavior evidence

The original function uses `this` in ECX. It frees a non-null old `distanceTable`, calls `malloc(256)`, saves the result, and fills 256 bytes with `0xff`.

The original then walks 17 `NormalLOS` pointers. The code reads each row until `y == 999`. It uses rows from 0 through 15. It clamps `x1` below zero and `x2` above 15. It writes each inclusive row range only when the table byte is still `0xff`. It stores the current distance as a byte.

Repository evidence agrees with this bound. `include/game_globals.h` declares 17 `NormalLOS` entries. `src/visible.cpp` initializes all 17 entries. The original code compares its cursor with the address of entry 16. The selected source uses `distance < 17`.

The candidate object has `NormalLOS` relocations at offsets 49 and 157. The bound operand at offset 157 has addend `0x44`. The relocation names `?NormalLOS@@3PAPAULOSTBL@@A`. Thus the raw `0x44` is a symbol-relative, one-past bound. It is not an absolute address. The candidate visits 17 entries.

Earlier experiment notes called raw zero or `0x40`/`0x44` operands null or invalid bounds. Later relocation checks disproved those claims. See the correction findings for states `5831bba7…`, `c1915e44…`, and `a2729926…` in `decomp_notes/experiments/`.

## Source and byte result

The selected loop uses `NormalLOS[distance]` and a normal integer bound. It preserves the row sentinel, clipping, inclusive writes, first-write rule, and distance width. The compiler keeps the original calls, symbol owner, function size, and boundary.

The remaining byte difference is localized to table-byte addressing and the outer-loop encoding. The original forms the cell pointer before its read and write. The rebuilt code uses indexed memory operands. The checker reports 10 differing bytes, two calls aligned, four relocations safely masked, and no boundary escape. It also reports a control-flow shape difference. The byte report alone does not prove behavior.

The countdown probe produced 191 bytes and changed stack cleanup order. It was not selected. The pointer-lvalue probe escaped the function boundary. It was not selected.
