## Behavior

The first branch tests `node->target_player` (`005324A7-005324AD`). If it is nonnull, the function scans only that player's object list. It compares each object's master `copy_id`, sign-extended from a short, with `node->obj_type` (`005324AF-005324D2`). A match sets state 0 and returns (`005324DF-005324E7`). An empty or exhausted list sets state 2.

If `target_player` is null, the function reads `this->player`, the signed-short world player count, and the players-array field before it tests the count (`005324EA-005324FB`). A nonpositive count sets state 2. Otherwise it scans players from index 0. It skips a player when the relation byte is zero or the index equals the signed-short player ID (`005324FF-00532511`). For other players it scans `objects->list` and compares each master `copy_id` with `node->obj_type` (`00532513-00532540`). A match sets state 0 and returns at `0053254D-0053255B`; exhausting the scan sets state 2 at `00532542-0053254A`.

The branch order matters. The target-player path does not read `this->player`. The global path loads `world->players` even when the count is nonpositive. No calls occur. Runtime and invalid-pointer tests were not run.
