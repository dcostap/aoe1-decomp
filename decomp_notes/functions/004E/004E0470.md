### Behavior

The original saves four registers and reserves one dword before reading the lot count.
It initializes index zero at `004E0477` and loads the signed count at `004E0479`.
A nonpositive count returns without reading the array pointer.
The positive path reads `buildingLots` at `004E0483` and saves that base at `004E0495`.
The scan compares `typeID`, X, and Y in that order, then advances by eight bytes.
It stops at the first match and leaves the count unchanged.

A status other than 3 writes only the status byte at `004E04C3`.
Status 3 first writes `typeID = -1` at `004E04DC`.
It then reloads `buildingLots` at `004E04E3`, `004E04ED`, and `004E04F7`.
Those loads precede the X, Y, and status stores, respectively.
The old source used one cached pointer for all four stores.
That lost the original pointer reloads when a store overlaps the pointer member.
The earlier valid-record review did not establish this alias behavior.

The function has no calls or relocations. No runtime fault or gameplay test ran.
