## Source

The source uses the reviewed `RGE_Player`, `RGE_Game_World`, `RGE_Master_Player`,
`RGE_Object_List`, `RGE_Visible_Map`, and `RGE_Doppleganger_Creator` declarations.
It has no raw offsets, wrappers, fake volatility, aliases, or inline assembly.
The member initializer list is period-plausible and is also used by the exact

The original first hunk schedules the scalar store for `pathingAttemptCapValue`
after the tile-list argument setup:

- original `+0x21`: `push 0x190`
- original `+0x26`: `lea ecx,[ebp+0x58]`
- original `+0x29`: `mov [esp+0x14],ebp`
- original `+0x2d`: `mov [ebp+0x8],5`

The rebuilt natural source emits the same instructions in a different schedule:

- rebuilt `+0x21`: `mov [ebp+0x8],5`
- rebuilt `+0x28`: `push 0x190`
- rebuilt `+0x2d`: `lea ecx,[ebp+0x58]`
- rebuilt `+0x30`: `mov [esp+0x14],ebp`

Reordering the member initializer text produced identical bytes. Moving all
scalar initialization into the body produced 79 differing bytes. Moving only
the pathing initialization into the body produced 64 differing bytes. These
forms also change the natural constructor model and were rejected.

The three differing instructions do not read parent state or call code, but this
does not prove equal fault behavior. The original executes `push 0x190` and the
stack-home write before `mov [this+8],5`. The rebuilt code performs the field
write first. A stack exhaustion fault can occur at the push or stack-home write.
The rebuilt object can then contain the pathing value while the original object
does not. Fault order and partial object state are therefore unresolved.
