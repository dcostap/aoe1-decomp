## Behavior

The original body first sign-extends `id` at `this+0x4A` into the checksum
prefix. It sets `checksum_created_this_update` at `this+0x20` to one and
clears `action_checksum` at `this+0x1C`. It then sign-extends the sleeping and
doppelganger list counts at `+0x2C/+0x30`, offset `+8`, and adds both to the
prefix.

When the signed `attribute_num` at `this+0x4C` is positive, the body reads
`attribute_num` floats from `this->attributes` at `+0x50`. Each float goes
through the direct `__ftol` call. The truncated signed result adds to the
32-bit attribute checksum. The pointer advances four bytes per iteration.
A non-positive count performs no attribute read.

The object loop reads `this->objects` at `+0x28`, then its list head at list
offset `+4`. For each node, it reads the object pointer at node offset zero.
It adds the object's byte `object_state` at `+0x48`, truncates its float
`attribute_amount_held` at `+0x44` through `__ftol`, sign-extends
`object->master_obj->id` at master offset `+0x10`, and calls the object's
virtual waypoint checksum at vtable offset `+0x1D4`. It increments the object
count and adds all three object coordinates at `+0x38`, `+0x3C`, and `+0x40`
to the single-precision position accumulator. It then calls the reread
`list->node` object's action checksum at vtable offset `+0x1D0`. It follows
`node->next` at offset `+4` after that call. The reread is required because
the waypoint call can change the list node's object pointer.

The original floating sequence is `world_x + old_position`, then `+ world_y`,
then `+ world_z`; it stores the result to a float local after every object.
The final position value goes through the direct `__ftol` call and stores the
result at `this+0x18`. The packed checksum is
`(((id + sleeping + doppelganger) * 0x100 + object_count) * 0x100 +
object_checksum) * 0x100 + attribute_checksum`, with 32-bit wrap in VC5. It
stores the packed value at `this+0x14` and returns it.

The retained source has the same checksum inputs, loop limits, arithmetic
widths, float conversions, coordinate order, reread, virtual slots, call
count, output stores, and return value for normal execution.

The retained code does not prove equal fault order. The original reads
`object_state` at `0047000C` before loading `attribute_amount_held` at
`0047000F`. Current VC5 codegen reads the held amount and calls `__ftol` before
reading `object_state`. A faulting object-state read or floating conversion can
therefore select a different first fault. This was not repaired with a fake
volatile or helper.
