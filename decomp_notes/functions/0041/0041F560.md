# Font setup: stack-object repair

## Behavior

The original keeps the font index outside the `TEXTMETRICA` object.
Use `S` for ESP after the saved-register pushes and before call arguments.

| Instruction | Address relative to S | Meaning |
| --- | --- | --- |
| `0041F5C4` | `+0x14` | Saved, sign-extended short index |
| `0041F681` | `+0x18` | Complete metrics output object |
| `0041F68D` | `+0x14` | Array index after the API call |
| `0041F6A8` | `+0x2C` | `tmAveCharWidth` |
| `0041F6B0` | `+0x18` | `tmHeight` |
| `0041F6B4` | `+0x28` | `tmExternalLeading` |

The last three reads follow two pushes at `0041F697` and `0041F698`.
Their printed ESP offsets include eight argument bytes.
Thus, the height store uses `tmHeight + tmExternalLeading`.
The width store uses `tmAveCharWidth`, not `tmMaxCharWidth`.

The baseline passed `&tm` but then used overwritten `tmHeight` as its array index.
A returned height of 16 writes entry 16 in a 12-entry array.
It also leaves the intended font slot empty. This is a proved source defect.
It can explain missing menu fonts and memory corruption. The reported crash cause remains unconfirmed.

## Source

The PDB scoped records name `short i` at `-0x40` and `tagTEXTMETRICA tm` at `-0x38`.
The executable supports those separate locals and the normal Win32 API object.
The decompiler places the metrics object four bytes too early.
Its apparent interior pointer and shifted field names are not source evidence.

The repair uses a counted loop, independent index, and complete metrics object.
It keeps the original font IDs, flags, null paths, selection, restoration, and DC release.
It preserves the allocation leak when DC acquisition fails.
No shared declarations, flags, helper functions, or assembly change.
