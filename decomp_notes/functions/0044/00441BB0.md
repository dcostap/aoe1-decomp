# 00441BB0 `recycle_in_to_game`

## Behavior

Re-review used the repo-local original executable and its complete inventory
packet. The packet's `PdbScopedSymbols` section gives `this` and all six stack
arguments: `tobj`, `obj_owner`, `x`, `y`, `z`, and `obj_to_dopple`.

The function clears the doppleganger fields before its base call at `00441C12`.
It passes the original five base arguments in their declared order. It then sets
the object type to `0x19` and records `obj_to_dopple`.

The original instructions at `00441BB0` through `00441BD3` load the five base
arguments and push them in reverse order. The clear stores are at `00441BD6`
through `00441C0C`. The call at `00441C12` enters
`RGE_Animated_Object::recycle_in_to_game`. Instructions `00441C17` through
`00441C27` set the type and store `obj_to_dopple` before the null branch.

For a non-null object, the function copies its master, owner ID, object ID,
sprite, sprite list, facet, and color data. The list-copy call at `00441C55`
receives `obj_to_dopple->sprite_list`. The call at `00441C5E` receives this
object's sprite list and the returned node.

The corresponding reads occur at `00441C2D`, `00441C36`, `00441C43`, and
`00441C4C`. Instructions `00441C52` through `00441C5E` perform the two sprite
calls. `00441C63` through `00441C6C` copy the facet. `00441C6F` through
`00441CA8` load the color table, map level, and selected map color.

At `00441CB2`, `__ftol` converts `y` to the row. At `00441CBD`, it converts
`x` to the column. The function indexes `unified_map_offsets[row]`, then adds
the column. It does not check these coordinates. Negative and out-of-range
coordinates keep the original unchecked access and fault behavior.

The original performs these conversions at `00441CA8` through `00441CC2`.
It loads the row base at `00441CC2`, clears the last value and hidden bits at
`00441CC9` and `00441CCF`, then stores the computed address at `00441CD8`.
The map table base in the original operand is `0x886808`.

The function clears `LastMapValue` and `CantSeeBits` before it stores
`MapAddress`. It checks `object_state` only after these operations. A state of
seven or more clears `doppled_object` and its ID, then calls `validate` at
`00441CF9`. A null object calls `destroy_obj` at `00441D1C`, then calls
`validate` at `00441D23`. The function does not skip either validation call.

The state read and comparison are at `00441CDE` and `00441CE1`. The high-state
path clears the object pointer and ID at `00441CE9` and `00441CEF`, then calls
the validation slot at `00441CF9`. The null path clears the ID, master, and
player fields at `00441D0A` through `00441D16`, then calls the destroy slot at
`00441D1C`. Both paths reach the validation slot at `00441D23` unless the
high-state path returns at `00441D03`.

The bytes support the field mapping in `include/dpl_obj.h`: object `+0x8C`,
draw color `+0x90`, master `+0x94`, player ID `+0x98`, map address `+0x9C`,
last value `+0xA0`, hidden bits `+0xA4`, map level `+0xA8`, map color `+0xA9`,
and object ID `+0xAC`. The header also checks the object size as `0xB0`.

No runtime boundary tests ran. The review traced null and non-null paths, state
values below and above seven, the two float conversions, all calls, and the
unchecked map access from original instructions.

## Source

PDB types and the header support the current owner, field, and parameter types.
`unified_map_offsets` is declared as 1024 pointers in
`include/game_globals.h` and defined in `src/game_globals.cpp`.

The source now uses `(int)y` and `(int)x`. VC5 targets 32-bit `int` and `long`.
The prior `(int)(long)` form added no conversion behavior. Both forms emit the
same two `__ftol` calls in the same order. The direct casts are simpler and
match the exact `setup` donor's conversion style.

Two natural map-address spellings were tested: row-pointer addition and
address-of-cell indexing. Neither changed the emitted function. The source keeps
the simpler pointer-add form. No unusual codegen helper or register forcing is
needed.
