# Streaming progress messages

## Canonical RIFF size repair

Base commit: `c6319679e`.

### Behavior

The random-game test reaches an integer divide-by-zero at rebuilt `0043F65C`.
The captured registers show ECX equals zero, the divisor for the progress percentage.
Evidence: `build/crash/map_setup/turn_step.log`.
The debugger stopped before the configured access-violation handler, so that run has no crash dump.

Original `00448B48` reads the divisor at `00888480`.
Original `0044871B` passes `0088847C` as the fourth argument to `WaveOpenFile`.
That argument is the RIFF `MMCKINFO` object.
`mmioDescend` writes its chunk size at offset four.
Thus `00888480` belongs to `ds_wave_riff_chunk.cksize`, not a separate scalar.
Original `00448773` also passes that RIFF object to `WaveStartDataRead`.

The rebuilt function instead read `ds_buffer_bytes`, a separate global that nothing writes.
Its zero initializer was not the defect. The duplicated storage was the defect.
ABI queries for both addresses find no indexed function-static owner.
Those negative query results do not prove ownership; the typed API call and original addresses supply positive evidence.

### Whole function

Message `0x500` calls `ds_stream_stop` and returns zero.
Message `0x502` reads the stream position and RIFF size.
It subtracts the size once when position exceeds size, then stores the reduced position.
It computes the unsigned percentage, converts through the original floating helper, and updates a changed percentage.
Other messages return zero without those effects.
The repair changes only the divisor's storage owner.
It preserves arithmetic widths, wrap behavior, division faults, calls, writes, and evaluation order.
No zero guard or compensating assignment was added.

### Source

`src/Dsutil.c` now reads `ds_wave_riff_chunk.cksize`.
`include/dsutil.h` and `src/game_globals.cpp` no longer declare or define the duplicate scalar.
Header consumers are Dsutil, Scr_game, and Game_globals.
The compiler gate covered the shared edits.

### Bytes

The baseline reported MATCH despite its wrong linked storage.
The repaired authoritative check reports `Result: MATCH`, 105 bytes, and `0.0000%`.
Owning symbol, boundary, calls, and relocation checks pass.
The relocation addend now addresses the actual RIFF member.
This repair shows why a narrow object-byte result does not establish shared storage ownership.

Experiments: `root-stream-baseline` and `root-stream-riff-size`.
Complete source patch: `decomp_notes/candidates/0044/00448B30_exact_candidate.patch`.
Full build `20260907T010029756169Z` succeeds.
