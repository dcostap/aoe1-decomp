# Function notes: 004CAC10 `get_armor`

## Behavior

- PDB ownership is `t_c_obj.cpp`, with `TRIBE_Combat_Object::get_armor` and a
  `__thiscall` ABI. The parameters are `short& cur_armor_in` at entry `+0x4`
  and `short& orig_armor_in` at entry `+0x8`.
- The original has no calls, no frame, and one return. It saves `ESI` and
  conditionally saves `EDI` around the armor scan.
- At `004CAC10`, the original loads `this->master_obj` from `this+0x8` before
  it loads the first output pointer. It reads `base_armor` at master `+0x100`
  as an unsigned byte and writes two bytes to `cur_armor_in`.
- It reloads `this->master_obj` at `004CAC23`, clears the 32-bit `EDX` index,
  and compares the signed `short armor_num` at `+0x102` with zero. A nonpositive
  count skips the scan. The loop reloads the master pointer at `004CAC4E` and
  rereads the signed count at `004CAC52` after each iteration.
- Each armor record is four bytes. The loop reads the signed `short type` at
  `armor + index*4`, then reads the signed `short value` at offset `+2` only
  when `type == 4`. It updates the first output with a two-byte store only
  when `value > cur_armor`.
- The original loads the second output pointer at `004CAC61`, then reads the
  signed `short orig_armor` at master `+0x13C` and writes two bytes. It has no
  null checks. Invalid `this`, master, armor pointer, record pointer, or output
  pointer can fault in the instruction order shown above.
- Repeated master loads are behavior-relevant. A first output reference can
  alias `this->master_obj`, `armor_num`, `armor`, or another field. The reloads
  make later accesses observe that store, or fault, instead of using a stale
  local pointer. No runtime harness was available; alias and fault claims are
  based on the original instruction order and equal rebuilt bytes.

## Source

- The retained source removes the unsupported local `master` alias. It uses
  repeated direct casts from `master_obj`, an `int i`, and the reviewed
  `RGE_Armor_Weapon_Info` fields. This matches the exact neighboring
  `RGE_Combat_Object::get_armor` source family in `src/com_obj.cpp`.
- The reviewed layout gives `base_armor` at `+0x100`, `armor_num` at `+0x102`,
  `armor` at `+0x104`, and `orig_armor` at `+0x13C`. The header checks the
  `RGE_Armor_Weapon_Info` size as four bytes and the combat-master size as
  `0x148`.
- `int i` is required by the exact donor and explains the 32-bit `EDX` index,
  increment, and signed `movsx` count comparison. The output and record values
  remain narrow `short` accesses. No wrapper, raw address, volatile access,
  inline assembly, or fake helper is used.
