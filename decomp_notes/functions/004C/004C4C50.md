## Behavior

The original guard reads `new_owner->master_objects[this->master_obj->id]`.
It returns when that entry is null.

The non-return path has nine calls in this order:

1. `owner->unselect_one_object(this)` when `selected & 1`.
2. `take_attribute_from_owner()` after computing `hp_num`.
3. This object's `vslot+0xDC(old_owner, 0, -1)` when `object_state == 2`.
4. Old-owner `vslot+0xE0(this, sleep_flag, dopple_flag, player_object_node)`.
5. New-owner `vslot+0xDC(this, sleep_flag, dopple_flag)`.
6. `vslot+0x38(new_sprite)` when the selected replacement sprite is not null.
7. This object's `vslot+0xD8(new_owner, 0, -1)` when `object_state == 2`.
8. `give_attribute_to_owner()`.
9. `vslot+0x148(id, id, 0x20B, (int)new_owner->id, 0, 0)`.

The old master pointer is read after `addObject`, then the returned node is
stored. The new master comes from `new_owner->master_objects[old_master->id]`.
The sprite map preserves the base, death, and undead aliases. Other sprites
use the new base sprite. The owner and master fields change after sprite work.
The new HP is signed `short` HP converted to `float`, multiplied by `hp_num`.

PDB evidence names `new_owner` as `RGE_Player*` at `+4`, `hp_num` as `float`
at `-8`, and `this` as `RGE_Static_Object*` in ECX. The original has no other
PDB local symbols. Header layouts prove the accessed master and player fields.
The static comparison covers null master entries, selected and unselected
objects, object states 2 and non-2, base/death/undead/other sprite aliases,
null replacement sprites, equal and different owners, and equal or different
master objects. There is no live runtime harness. Fault order is checked from
instruction order.
