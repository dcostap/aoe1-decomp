# Function notes: 004AB670 `set_unit`

Module notes: `decomp_notes/scr_sed.md`.

## drift-010 behavior re-review

### Behavior

- The original compares the short argument with `-1` at `004AB675`.
  That path stores `-1` in `master_obj_id` and calls
  `scroll_cur_line(1, val, 1)`.
- For other values, the original sign-extends the argument, reads the row ID
  at `unit_list_info[val] + 0x64`, stores it in `master_obj_id`, then loads
  `unit_list` and calls `scroll_cur_line(1, val, 1)`. The source keeps the
  sentinel, ID, and call arguments. It adds no bounds check.
- The original does not check the index before reading the row. Known callers
  use `-1` or a line from `unit_list`. Invalid indices and damaged list state
  were not tested.
- Open fault-order point: the rebuilt call setup pushes its three arguments
  before it reads the row ID. The original reads and stores the ID first, then
  pushes the arguments. An invalid row can fault after different stack writes.
  No valid caller case was found that triggers this fault.

### Source

- The natural source uses `unit_list_info[val].id` and one direct panel call.
- A tested local `TListPanel *list = unit_list` after the ID update did not
  change compiler output. The source was restored to the simpler expression.
- A second test stored the selected ID in a short local, then shared the global
  store and panel call. It changed source call-site topology and was rejected.
