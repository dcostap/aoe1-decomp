- ABI/numeric reviewer found no blocking result, width, loop, `__ftol`, ABI, or

  but found that both coordinate equalities are spelled in the reverse operand

  `param_1` on the left for both coordinate comparisons.
- Full machine-effect reviewer independently confirmed both defects. It also
  identified changed upper-EAX residue on a Y mismatch and a stack-alias case in
  which the candidate's earlier callee-save push could overwrite a count byte
  before reading it. Verdict: needs attention.

## Runtime declaration closure at `07a557c05`

Decision: do not approve the current nine-byte difference as accepted drift.
The checker reports 153 bytes, 64 instructions, and four conversion calls in both bodies.
Ownership and boundaries pass, but equal call names do not prove equal arguments or fault order.

At `+0042`, the original loads the incoming record's y coordinate from `[EBX+0x10]`.
It converts that value before loading and converting `[ESI+0x10]` from the previous record.
The rebuild loads and converts the previous record first.
Both compare equal low-sixteen-bit conversion results, but their first fault can differ.

Concrete memory example derived from the instructions:

- Set EBX to `P-0x10` and ESI to `Q-0x10`, where P and Q are different page boundaries.
- Map both preceding pages and leave pages P and Q unreadable.
- Give both records equal count bytes and equal zero x coordinates at offset `+0x0C`.
- Supply a readable command object containing the previous-record pointer.

The count and x-coordinate checks succeed in both versions.
The original then faults reading P; the rebuild faults reading Q.
This example uses instruction semantics; it is not a claimed executed test.
It establishes a memory-fault difference without assumptions about exceptional floating-point values.

The two unit-array pointer homes also exchange private stack slots.
The earlier reviews already identify stack-overlapping records as relevant to this function.
That part requires renewed alias review as well.
