```text

```

The arithmetic is 32-bit, including wraparound.
Changing the addition grouping preserves every address bit.
Both use `y & 3` to index the same shift and mask tables.
Both read the obstruction byte, then the shift-table byte.
They extract the same two-bit count and leave zero counts unchanged.
For a nonzero count, both read the same mask byte and perform the same byte operations:
mask the other bits, decrement the selected count, shift it, combine it, and store it.
The data-read order, data-write address, stored value, and branch predicate agree.

EDI is restored, and the function has no return value.

## Remaining stack-fault issue

The original saves eight bytes of registers; the rebuild saves twelve.
The extra push occurs before the first obstruction access.
Equal data accesses do not alone prove equal behavior at stack exhaustion.

For an instruction-level boundary example, let P be the lowest writable stack address.
Set entry ESP to `P+8`, with readable arguments and a valid zero-count obstruction byte.
The original pushes to `P+4` and P, then returns normally.
The rebuild's third push reaches `P-4`.
If that address cannot receive another stack page, the rebuild faults instead.
This is a constructed boundary case, not a claimed Windows runtime test.

Approval therefore needs a supported stack-capacity precondition or a natural repair that preserves the required behavior.
Do not silently exclude stack exhaustion while claiming unconditional exception equality.
Do not add dummy source or padding to force a register save pattern.
