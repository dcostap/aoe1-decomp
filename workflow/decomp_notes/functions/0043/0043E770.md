# Function notes: 0043E770 `draw`

Module notes: `workflow/decomp_notes/dlg_dip.md`.

## Behavior

The original body is `0043E770-0043E832` and has 195 bytes. Its owner is the
protected virtual symbol `?draw@TribeDiplomacyDialog@@MAEXXZ`.

The original call and memory order is:

1. Call `TEasy_Panel::draw()` at `0043E777`.
2. Read `backgroundPics` at `this+0x60C`, clear the row offset, and branch on
   the pointer.
3. Read `rge_base_game->world`, then call virtual slot `+0x28` with `this`
   and zero.
4. Read `world->player_num`. For each player from `world->players[1]` through
   the current count, read the player color table and skip null tables.
5. Call `ASMSet_Color_Xform((color_table->id + 1) * 16)`.
6. Reread the player color table for `shape_draw` and pass its `table` field.
7. At the loop bottom, reread `player_num`, add `0x1E` to the row offset,
   advance the player cursor, increment the row counter, and branch while the
   row is below `count-1`.
8. Call virtual slot `+0x2C` with `this`.

The retained source has the same five calls, order, receivers, arguments, field
reads, loop bounds, and branch topology. The shape call rereads
`world->players[i + 1]->color_table->table`, as the original rereads the player
and color table after the color-transform call.

No runtime fixture was supplied. Null background, null color table, count zero,
changing world pointers, allocation failure, and malformed object states were not
dynamically tested. Static instruction tracing covers the null branches and the
read order. The direct color-transform call has no memory access to the dialog
or world storage in the preserved drawing dependency.

### Behavior

The original range is `0043E770-0043E832`, with a 195-byte body. The symbol is
`?draw@TribeDiplomacyDialog@@MAEXXZ`. The original packet is
`inventory/functions/0043/0043E770_draw.txt`.

The first call at `0043E777` directly calls `TEasy_Panel::draw()`. Its complete
packet is `inventory/functions/0046/00467570_draw.txt`. It may call
`setup_shadow_area(1)` and virtual slot `+0xE0`. Both builds call it before
reading `backgroundPics`.

At `0043E77C`, the function reads `this+0x60C`, then clears `EBP`. At `+0x14`,
the original compares the shape pointer with zero. A zero pointer branches to
the epilogue. It skips all later calls and world reads.

For a nonzero pointer, `0043E78C` reads `rge_base_game`, then `world` at game
offset `+0x3F4`. It saves the dialog vtable before calling slot `+0x28` at
`0043E7A2`, with `this` and integer zero. It reads signed-short
`world->player_num` at `+0x35`, subtracts one, and skips the loop when the
result is nonpositive. Negative and zero counts also skip the loop.

Each iteration starts at player index one. At `0043E7BA`, it rereads
`world->players` and the indexed player. It reads that player's color-table
pointer at `+0x108`. A null table skips both drawing calls, but still advances
the row, player index, and array offset.

For a nonnull table, `0043E7C7` sign-extends its short `id` at `+0x26`, adds one,
and shifts left four bits. The call at `0043E7D0` passes that integer to
`ASMSet_Color_Xform`. Its complete packet is
`inventory/functions/0056/0056C760_ASMSet_Color_Xform.txt`. It writes the
process transform at `0x88C040` from the low argument byte. It does not write
the dialog or world.

After that call, the original rereads `world->players`, the player, and the
color table. It passes `table` at color-table offset `+0x28` to `shape_draw`.
The call at `0043E805` uses `backgroundPics` as `this`, then passes
`render_area`, `pnl_x+10`, `pnl_y+row+80`, shape index zero, flags one, and the
table pointer. `inventory/functions/004B/004B9440_shape_draw.txt` confirms six
stack arguments, a `thiscall` receiver, and callee cleanup with `ret 0x18`.
The return byte is ignored.

At the loop bottom, the function rereads signed-short `player_num` at
`0043E80A`. It adds `0x1E` to the row, advances the player-array offset by four,
increments the signed integer index, and compares it with `player_num-1`.
Thus it observes count changes between iterations. After the loop, it calls
virtual slot `+0x2C` at `0043E828`, using the saved vtable and `this`.
`inventory/functions/0046/00465370_draw_finish.txt` identifies the inherited
`TPanel::draw_finish()` body.

The current source reads the same typed fields and keeps the same call order.
It caches `world` before `draw_setup`, as the original does. It rereads the
player array and color table for `shape_draw`. The `player_num` and color-table
fields are signed shorts in `include/world.h` and `include/color.h`.
`include/player.h` and `include/dlg_dip.h` provide the typed owner fields.
The source's loop covers indices one through `player_num-1` for every signed
short count. The code also preserves the original null branches and call order.

The PDB scoped-symbol record is in `inventory/pdb/scoped_symbols.json` at
`0043E770`. It proves `this` is a `TribeDiplomacyDialog*`. It reports no stack,
static, or local symbols. This absence does not prove that source locals did
not exist.

No runtime fixture was available. Runtime checks for null background, counts
at or below one, null players, null color tables, changing counts, and invalid
objects remain untested. Static tracing checked their encoded paths. Array
capacity and game-state validity remain caller obligations.
