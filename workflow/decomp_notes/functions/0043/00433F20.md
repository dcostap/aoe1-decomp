## Behavior

The original function is 880 bytes and uses `__thiscall`. The PDB names the owner
`RGE_Command::do_command_order` in `Command.obj`. It names the parameter `order`,
`target`, `units`, `index`, `unit_num`, eight float locals, and the register `this`.

`RGE_Command_Order` is a 0x14-byte header. The original reads these fields:

- target object ID at `+0x4`;
- unit count byte at `+0x8`;
- destination X and Y at `+0xC` and `+0x10`;
- the serialized `RGE_Obj_Info` array at `+0x14`.

The source uses the reviewed header and computes the array address with
`sizeof(*command)`. This emits the original `lea [order+0x14]`.

The original call sequence is:

| Offset | Call | Source operation |
| --- | --- | --- |
| `+0x25` | direct `get_obj` | Load the command target. |
| `+0x76` | direct `get_obj` | Load one unit while measuring bounds. |
| `+0x16A` | direct `get_obj` | Load one unit for a grouped order. |
| `+0x17B` | direct `removeAllFromPathingGroup` | Remove the unit from its old group. |
| `+0x186` | virtual slot `+0x12C` | Set waiting-to-move to `1`. |
| `+0x19D` | direct `addToPathingGroup` | Add every other serialized unit ID. |
| `+0x29E` | virtual slot `+0x98` | Issue the adjusted order. |
| `+0x2EB` | direct `get_obj` | Load one unit for the simple order. |
| `+0x2F8` | direct `removeAllFromPathingGroup` | Remove the unit from its old group. |
| `+0x303` | virtual slot `+0x12C` | Set waiting-to-move to `1`. |
| `+0x31A` | direct `addToPathingGroup` | Add every other serialized unit ID. |
| `+0x340` | virtual slot `+0x98` | Issue the command destination order. |

The call map aligns all 12 calls. It reports no target-count or direct-symbol
change. The two virtual calls pass the same receiver, target choice, X, Y, and
zero argument as the original.

For more than one unit, the source measures X and Y bounds and totals. It takes
the grouped path only when both spans are at most `DAT_0056f4d8`. It divides the
totals by the original byte-derived count. It then removes each unit from its
pathing group, sets its waiting state, adds all other unit IDs, adjusts both
coordinates, clamps them against the map, and issues the target order only when
the target has a positive radius. Otherwise it issues a null-target order.

The simple path preserves the original order. It removes each unit, sets its
waiting state, adds the other units, and issues the command target with the
packet destination. A null object skips the unit body but still advances the
serialized cursor and loop index.

The original stack frame is `0x28` with saved `EBX`, `EBP`, `ESI`, and `EDI`.
The rebuilt frame and saved-register set are identical. The original stack map
shows reused homes for the float locals and loop index. The rebuilt source uses
ordinary locals and preserves those reuse opportunities without raw stack
arithmetic.

Static review covers all branches, loop bounds, serialized cursor advances,
call receivers, call arguments, global reads, stack locals, and cleanup. No
runtime game test was available. The two changed reloads read compiler-owned
stack homes after the same virtual call. A malformed or unmapped process stack
could expose their order as a fault-order difference; that pathological case is
not independently executable here.
