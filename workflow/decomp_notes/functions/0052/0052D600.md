# Function notes: 0052D600 `mouse_left_up_action`

## Behavior

**Facts from the original executable:** `inventory/functions/0052/0052D600_mouse_left_up_action.txt` contains the complete body, `0052D600-0052D94B`.

- At `0052D608`, the function reads `rge_base_game->prog_mode` before other calls.
- It returns zero unless the mode is 4, 6, 7, or 5.
- At `0052D633`, it calls `get_paused`; a nonzero result delegates to `RGE_Main_View::mouse_left_up_action`.
- At `0052D640-0052D657`, it dispatches game modes 100 through 105. Other values delegate to the base method.
- The fallback at `0052D780` forwards `x`, `y`, `ctrl_key`, and `shift_key` in source order.
- The fallback direct target is `0053E910`. The function has no loop.
- Every handled mode calls `release_mouse` before testing the one-byte `mouse_action` field.
- Only field values 1 and 2 continue. Other values return one without resetting game mode.

- The 20-byte write fits the local and ends before the return address and saved registers.
- `fixup_pick_info` runs only after pick status `0x33`; it clamps `x` before `y`.
- Original `00540680` returns immediately after setting negative `y` to zero.
- Attack and unload receive the two float fields, in `(x,y)` order.
- Repair tests the target pointer before the call. It reads the target ID only after repair succeeds.
- Handled command failures play sound before the game-mode reset. Invalid mouse actions skip both.
- Assembly shows four returns, the `0x14` local frame, and `ret 0x10` cleanup.
