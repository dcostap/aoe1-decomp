## Behavior

The original body spans `0045BA60-0045BD57` and has 760 bytes. PDB proves
`ECX TMousePointer* this`, `+4 int dMode`, and `-4 IDirectDrawClipper*
lplpDDClipper`. It lists no other stack locals. The checked class size is
`0x254`.

The function returns unless `active` and `custom_draw` are nonzero. It calls
`debug_timeGetTime` with the original file string and line 739. Only when
`GameMode`, `GameEnabled`, and `dMode == 0` does it throttle. It subtracts
unsigned 32-bit `LastDrawTime` and skips when the result is below `0x22`.
Thus wraparound and the exact `0x21`/`0x22` boundary remain significant.

It calls `update_mouse_position(this)`. A zero result skips work only when
`dMode == 0`. It stores `LastDrawTime` before later drawing calls. If saved
pixels are valid and `restoreSurface != PrimarySurface`, it calls
`restoreSurface->Blt(&restore_rect, save_area->DrawSurface, &save_rect,
DDBLT_WAIT, 0)`. Failure stores `LastddError` and returns.

When `MouseOnScreen` is nonzero, it saves the current rectangle with
`save_area->DrawSurface->Blt(&new_save_rect, renderSurface, &mouse_rect,
DDBLT_WAIT, 0)`. Failure returns before the following state writes. Success
sets `restoreSurface`, copies the rectangles, and sets `save_area_valid`.

For `Mouse_Mode == 0`, it gets the render surface clipper. Error
`0x88760238` becomes success with a null clipper. Other errors store
`LastddError` and return. A nonnull clipper is removed with
`SetClipper(NULL)`; failure returns. For `Mouse_Mode == 1`, it locks
`render_area` with `("mouseptr::draw", 1)`. On success it calls
`Cursor_Shape->shape_draw` with `render_area`,
`shape_info[next_facet].Hotspot_X + mouse_rect.left`,
`shape_info[next_facet].Hotspot_Y + mouse_rect.top`, `next_facet`, zero flags,
and a null color table. It ignores the draw result and unlocks.

For `Mouse_Mode == 0`, it calls `SetTrans(1, 0)` on
`cursors[next_facet]`, then calls `renderSurface->BltFast(mouse_rect.left,
mouse_rect.top, cursor.DrawSurface, &cursor_rect, 0x11)`. A blit error stores
`LastddError` and returns. The function sets `last_facet` before restoring a
saved clipper. A clipper-restore error also returns. These early returns can
leave a removed clipper unrestored. This is an original cleanup defect; the
source preserves it.

If `MouseOnScreen` is zero, it clears `save_area_valid`. It calls
`InvalidateRect(render_area->Wnd, &mouse_rect, FALSE)` only when either game
mode or game enable is zero. It then sets `drawn` to one. A failed lock skips
shape drawing but still reaches `last_facet`, invalidation, and `drawn`. Modes
other than zero or one also skip mode-specific drawing but update `last_facet`.

The assembly confirms all 13 call sites and their argument order. They are
`debug_timeGetTime`, `update_mouse_position`, two `Blt` calls, `GetClipper`,
two `SetClipper` calls, `Lock`, `shape_draw`, `Unlock`, `SetTrans`, `BltFast`,
and `InvalidateRect`. COM calls use the declared DirectDraw virtual methods.
Static review covered each branch, error return, state write, and argument.
Runtime tests with DirectDraw were not run. Linked storage and concurrent
mutation effects were not tested.

## Source

The final source removes `ptVar1`, which only aliased `&this->mouse_rect`.
It uses typed `mouse_rect` fields and its address directly. A separate state
changed `f` from `long` to `int`, matching the `next_facet` field. Both are
32-bit signed types under the pinned VC5 target. `shape_draw` still receives
the same 32-bit value as its `long` parameter. The source retains a typed
`Shape_Info* si` base and indexed hotspot reads.

The original assembly computes `shape_info + next_facet` with a five-bit
shift. `sizeof(Shape_Info)` is `0x20`; both hotspot fields are `long`. No
pointer-local or type change alters the observed call arguments. The source
keeps the original early-return cleanup behavior. It adds no manual vtable,
raw offset, fake helper, or inline assembly.
