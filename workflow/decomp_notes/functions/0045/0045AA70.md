# 0045AA70 `RGE_Missile_Object::missile_move`

## Behavior

The original reads `world_x` at 0045AA76 before `velocity_x` at 0045AA79. It reads `velocity_z` at 0045AA7F next.

It then reads `world_y` at 0045AA85 before `velocity_y` at 0045AA88. These orders control the first unmasked signaling-NaN exception.

The baseline reverses each x and y pair. Therefore, the prior accepted-drift proof is not complete.

Sequenced x and y statements fix each pair. However, they read `world_y` before `velocity_z`. They also delay the `velocity_y` read until after the x comparison and z addition.

Those changes alter fault and signaling-NaN order. No tested ordered form preserves the complete original sequence.

The two virtual calls remain `die_die_die` at slot `0x6c` and `teleport` at slot `0x34`. Their receivers, arguments, and cleanup match in every size-valid tested form.

## Source

Generated PDB layout evidence owns `velocity_x`, `velocity_y`, and `velocity_z` in `RGE_Moving_Object` at offsets `0x90`, `0x94`, and `0x98`.

An older exact fragment used unsupported direct `dx`, `dy`, and `dz` fields in a local class view. The canonical hierarchy does not own those names in `RGE_Missile_Object`.

The final state restores the canonical source. It retains the known defect and is not an accepted-drift proposal.
