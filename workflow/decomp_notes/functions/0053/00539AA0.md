## 2026-09-10 current-main recovery pass

### Behavior

- The PDB names the inputs `terrain_type`, `tile_type`, `map_col`, and
  `map_row`. The first two are unsigned bytes. The coordinates are signed
  shorts.
- The function reads `this->map`, then `terrain_types[terrain_type]`. It tests
  that terrain shape before it reads `tiles[tile_type].count`.
- A zero count returns `-1`. For counts greater than one, rows and columns are
  truncated to unsigned bytes. The row index uses `map_row % rows`. The column
  index uses `map_col % cols`. A zero dimension gives index zero.
- The linear frame index is `row * cols + col`. Values above `count - 1` reset
  to zero. The return is `animations * index + shape_index`, narrowed to short.
- No elevation input is read. The function does not use `RGE_Tile::height` or
  `RGE_View::elev_hgt`; its coordinate conversion is only table modulo math,
  not screen-coordinate projection.
- There are no calls. There is no explicit terrain or tile bounds check. Null
  `this` or `map`, and out-of-range byte indices, fault in the observed read
  order. Negative signed remainders are narrowed to unsigned bytes.

### Source

- `src/view.cpp` is the canonical owner. `include/view.h` declares the
  protected member with the PDB-supported ABI. `include/map.h` owns the
  `RGE_Tile_Set` and `RGE_TOB_Picts` layouts: tile records are six bytes and
  `tiles` starts at the proven terrain-set offset.
- The living source uses separate unsigned-byte `rows`, `cols`, `row`, and
  `col` locals. This removes unsupported parameter aliasing while preserving
  the observed values, order, and faults.
- The original compiler reused the `tile_type` and `terrain_type` argument
  homes for `rows` and `cols`. The PDB records this overlap at `+0x8` and
