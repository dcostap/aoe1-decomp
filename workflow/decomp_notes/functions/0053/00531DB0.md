Module note: `workflow/decomp_notes/victory.md`.

## Behavior

The original returns before any write when `victory_list` is null (`00531DB9-00531DD0`). For a nonnull list, it clears `victory` at `00531DD8`, then clears each entry's `checked_flag` at `00531DDD-00531DE5`.

The outer scan finds the first unchecked entry and reads its byte `victory_group` (`00531DF6-00531E10`). It scans the full list for that group. It counts every member, marks each checked, records state 1 as success, counts state 2, and adds state 3 to one global failed counter (`00531E1E-00531E4D`). Other state values count as members but do not change those counters.

A successful group increments `group_num` and starts the next group (`00531E4F-00531E58`). A group without success sets `victory` to 2 only when its completed count is positive and its member count equals the accumulated failed count plus completed count (`00531E5A-00531E6C`). The function then sets `victory` to 1 when discovered-group count equals successful-group count (`00531E70-00531E7C`). The global failed counter and final overwrite are original behavior. Do not normalize them.

No calls occur. Empty-list behavior, writes, signed dword counters, byte group values, and branch order are visible in the cited instructions. Runtime and corrupt-list tests were not run.
