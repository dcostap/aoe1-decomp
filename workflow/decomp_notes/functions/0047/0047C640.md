# Function notes: 0047C640 `word_wrap_append`

Module notes: `workflow/decomp_notes/pnl_txt.md`.

## Source inspection after broken help wrapping, 2026-09-06

The fitting loop advances `next_char` twice but increments `chars` only once.
The first advance precedes measurement. The second follows a successful fit.
Thus, the measured prefix and copied character count diverge, even for ASCII text.
This can produce short lines and split words, as the user reported.

The original differs. At `0047C815`, `_mbsinc(edi)` supplies a measurement endpoint without replacing EDI.
Only the call at `0047C848` advances the stored cursor, through `mov edi,eax` at `0047C854`.
The proposed repair must preserve this look-ahead operation and advance the cursor only once per accepted character.
No source repair or new compiler check accompanied this inspection.
The earlier statement that the source preserves all original break paths needs renewed review.
