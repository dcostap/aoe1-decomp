### drift-064-pnl_lst accepted-drift re-review

#### Behavior

The original packet at `inventory/functions/0047/004786B0_item_at.txt` assigns
`this` to ECX, `x` to entry stack `+4`, and `y` to entry stack `+8`. It has no
function static. The code at `004786B0-004786F1` reads `spacer_size` at
`this+0x184`, `text_hgt` at `+0x140`, `y`, `border_size` at `+0x180`, `pnl_y`
at `+0x10`, and the 16-bit `top_line` at `+0xFC`. The class declarations in
`include/pnl_lst.h` and `include/panel.h` support those signed widths and fields.
`x` is unused. There are no calls or object stores; the pushes save ESI/EDI on
the stack.

If `spacer_size` is zero, the signed divisor is `text_hgt`. Otherwise it is
`text_hgt + 2 * spacer_size - 1`, using the executable's 32-bit arithmetic.
The signed dividend is `y - border_size - pnl_y - spacer_size`. `IDIV` truncates
toward zero and faults for a zero divisor or `INT_MIN / -1`. The quotient is
added to `top_line`, then narrowed to `short`. The executable has no guard for
either division fault. It pushes ESI/EDI, restores both on the normal path, and
returns with `ret 8`.

The current source build reads/subtracts `pnl_y` before `border_size`; the
original does the reverse. These are distinct fields of a valid `TListPanel`.
The subtraction order gives the same 32-bit result modulo 2^32. No call, write,
or aliasing effect occurs between the reads. Thus no behavior difference is
proved for a valid object. The fault order for an invalid or truncated `this`
pointer differs and is outside the valid-object precondition. No runtime test
was run.
