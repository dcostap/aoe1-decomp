## 2026-09-10 fresh exact review

### Behavior

The function returns `0` when `input_pos >= input_len`. Otherwise it switches
the active double buffer, copies the prefix, and removes one character or a
line ending at the cursor. A CRLF pair removes two bytes. A LF preceded by CR
also moves `input_pos` back by one. It then copies the tail, updates
`input_len`, reformats text, recalculates the cursor, enables the caret, and
stores `debug_timeGetTime`.

The original reads `input_len` at `+0x1AC` and `input_pos` at `+0x1B4`.
It selects buffers at `+0x1A0`, `+0x1A4`, and `+0x1A8`. It writes
`input_len`, `draw_caret` at `+0x194`, and `caret_last_time` at `+0x190`.
The source preserves these widths and write order. It preserves the null and
empty paths shown by the original: no buffer dereference occurs before the
initial length test, but active buffers are then required.

All 14 calls have equal targets and argument order. They are eleven multibyte
cursor and copy calls, `reformat`, `calc_cur_line_col`, and
`debug_timeGetTime`. No callback or virtual call occurs in this body. Re-entry
through the two direct helpers remains an external concern. Malformed buffer
pointers, invalid cursor values, multibyte faults, and helper re-entry were
not runtime tested.

## 2026-09-28 reopened accepted-drift review

### Behavior

The original body is `00477AF0-00477C87`, 408 bytes. The signed word guard at
`00477AF6-00477B04` returns zero when `input_pos >= input_len`; it does not
switch buffers or touch text. The PDB type and class layout put these signed
short fields at `+0x1B4` and `+0x1AC`. On the other path, the body chooses the
other input buffer and stores it to `input_buffer`. It clears that buffer's
first byte before any prefix copy. A bad destination faults after the pointer
field changes. The prefix copy and both cursor advances run only when
`input_pos > 0`.

At `+0x99`, the original tests the next character for CR. It advances with
`_mbsinc`, then removes a following LF too. For LF, it checks that the cursor
is not at the source start, steps back one multibyte character, and checks for
CR. A CR-LF pair removes two characters and backs the destination cursor and
`input_pos` up by one; other cases remove one. Direct byte tests for CR and LF
are preserved. The final `_mbsncpy` copies from the byte after the removed
sequence to `cur_dest`, with signed-int count `input_len - input_pos + 1`.
Then the body optionally decrements `input_pos`, subtracts one or two from the
short `input_len`, calls `reformat`, calls `calc_cur_line_col`, sets
`draw_caret`, calls `debug_timeGetTime` with the source path and line `0x2F6`,
stores its result, and returns one.

The 14 original calls are 11 multibyte CRT calls, direct `reformat`, direct
`calc_cur_line_col`, and `debug_timeGetTime`. Their order and branch placement
match the source. The two prefix/final `_mbsncpy` calls use destination, source,
count order; prefix count and both `_mbsninc` counts come from sign-extended
`input_pos`. `_mbsdec` receives base then current pointer. `_mbsninc` uses
count two for the LF-pair paths. The PDB scoped-symbol packet proves
`cur_dest` is `unsigned char*` at stack `-0x8`, `move_back_one` is `int` at
`-0x4`, and `this` is `TInputPanel*` in ECX.

Boundary review: empty text with position zero returns zero before a buffer
read. Position equal to or above length also returns zero. A negative
position below length passes the signed guard and skips prefix copying. It
starts deletion at the source's first byte. This unusual case is preserved.
DBCS stepping uses the CRT cursor calls. CR and LF at the cursor follow
separate paths. CR-LF pairs and LF after CR follow other paths. Ordinary
characters follow the single-character path. These are static instruction
traces, not runtime tests. Malformed buffer pointers and invalid positions
remain untested. DBCS fault cases and helper re-entry also remain untested.
The body preserves all observed writes, calls, and branch order. One rebuilt
instruction hunk loads `input_pos` before `input_len`; the original loads
`input_len` first. These are ordinary field reads with no call or write between
them. For a valid, stable `TInputPanel`, both values feed the same signed-int
count. An invalid, partly mapped `this` could fault on a different read.
Concurrent mutation could also expose a different value order. Neither case is
proved equivalent or runtime tested. No behavior defect was proved for valid
objects.
