## 2026-09-28 accepted-drift re-review: `drift-039-pathsys`

### Behavior

- The original starts by selecting the normal or exception path from
  `currentObject->storePathInExceptionPath` and calls `killPath` at
  `0046D839-0046D855`. `Path::killPath` clears `currentSizeValue` and
  `currentWaypointValue`.
- Instructions `0046D85A-0046D8AF` read the first open-path byte coordinates,
  read `facetValue[x][y]`, and select its low three facet bits only when its
  upper five bits equal `CurrentFacetMask`. Otherwise, the facet is `0xFF`.
- `0046D8B6-0046D901` writes waypoint coordinates as integer-to-float values
  plus the current offsets, copies `currentObject->world_z`, stores the facet,
  and calls `Path::initToStart`. The original stack slot for `Waypoint wp` is
  `-0x10`; its meaningful fields fit before the return address.
- `0046D906-0046D95C` checks the initial tile. It inserts the waypoint and
  returns 0 on insertion failure. `0046D962-0046D9C1` skips the object scan
  when the current unobstructible group is `-1`; otherwise it clamps a
  three-by-three scan at each edge. The original `if/else if` order can still
  scan coordinate 2 when a dimension is 1.
- `0046D9E5-0046DA0C` calls
  `RGE_Game_World::objectGroupOnTile(world, playerID, groupID, tileX, tileY,
  &objectCountOnTile)`. The pushes are output pointer, `tileY`, `tileX`, group,
  then player; ECX is the world. The zeroed four-byte output local is not read
  by this function. The callee uses `ret 0x14`.
- Other direct calls are `Path::killPath` at `0046D855`,
  `Path::initToStart` at `0046D901`, and `Path::insertAtCurrent` at
  `0046D93B`, `0046D955`, `0046DC48`, and `0046DC66`. Each insert call gets
  the selected path in ECX and `&wp` as its one 16-byte waypoint reference;
  its callee uses `ret 4`. Array growth calls `operator_new` at `0046DA5D`
  with `(number + 1) * 4` bytes and `operator_delete` at `0046DA9B` with the
  old value pointer. The caller removes each four-byte argument. No call order
  or argument differs in the rebuild.
- `0046DA13-0046DAC9` ignores `-1` results, avoids duplicate object IDs, and
  grows the array only when needed. The original duplicate loop and capacity
  copy at `0046DA1C-0046DAA9` match `ManagedArray<int>::add` in
  `include/utmarray.h`, including copying allocated slots and the unchecked
  append if allocation returns null. The callee also skips duplicate IDs.
- `0046DAF5-0046DBB7` applies all eight facets to byte coordinates. The step
  size is read as one byte; additions and subtractions wrap at 8 bits. An
  invalid facet takes the switch default and does not move. `0046DBC5-0046DC28`
  reads the next facet and rebuilds the waypoint. `0046DC2D-0046DC87` performs
  the final path insertion and returns 0 or 1. Every exit uses `ret 4`.
- The original has two unbounded-loop cases: a zero low byte in `stepSize`, or
  an invalid `0xFF` facet, can leave the coordinate unchanged when it differs
  from `initialTile`. The source preserves both. No runtime cases were run.
- The function accesses `facetValue` before calling the callee's map-bound
  checks. It has no local coordinate bounds check. Invalid object state can
  fault at those reads; no runtime fault-order test ran.
