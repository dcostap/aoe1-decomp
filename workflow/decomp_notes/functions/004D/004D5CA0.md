# Function notes: 004D5CA0 `readyToResearch`

## Classification

`BLOCKED`. The registry status is unchanged. Recommend demoting this owner to
`scratch` until the strict stack-fault behavior is resolved. The retained
source is a policy improvement: it removes fake volatility and pointer

## Behavior

The original body is 145 bytes and uses `__thiscall`. The original has two
inputs: `int id` at entry stack `+0x4` and `int ageResearch` at `+0x8`.
PdbScopedSymbols also records the `unsigned char rState` result local. The
original body has no exception frame and no object-memory writes.

The complete branch and call review is:

| `ageResearch != 1` | `004D5D1E researchState(id)` | same target and argument |
| `ageResearch == 1 && id == 2` | `004D5CC4 researchState(0x65)` | same target and argument |

For `id == 2`, the call at `004D5CC4` is followed by the `id == 3` and
`id == 4` tests. For `id == 3`, only the `0x66` call runs. For `id == 4`,
the `0x67` call returns through the special path. Other IDs in the
`ageResearch == 1` path use the low byte of `id` as `rState`. The natural
`unsigned char` assignment has the same modulo-256 result as the original
x86 low-byte stack load, including negative and high-bit `int` values.

Every call loads `this->md` from `+0x5BC` and `md->aiPlayer` from `+0x1256C`.
The rebuilt object retains those offsets, all four direct relocations, the
`TRIBE_Player::researchState(int)` symbol, call order, call count, predicates,
and `ret 8` cleanup. The called method returns `unsigned char`; both bodies
compare its low-byte result with `1` and return an `int` zero or one.

The natural rebuild changes the saved-register prologue. The original writes
ESI, compares `ageResearch`, then writes EDI. The rebuild writes EBX, writes
ESI, then compares `ageResearch`. Both writes target the two saved-register
stack slots and both registers are restored before `ret 8`. The push writes
can fault. Therefore the changed push order is a strict stack-fault and
exception-order difference. The source is not safe to classify as accepted
drift, even though valid game calls use a writable caller stack. The object
and result memory are otherwise read-only in this function. No C++ exception
path or EH cleanup exists in either body.

## Source

The repaired source is a direct typed form:

```cpp
int TribeBuildAIModule::readyToResearch(int id, int ageResearch)
{
    unsigned char rState;
    if (ageResearch == 1) {
        if (id == 2)
            rState = this->md->aiPlayer->researchState(0x65);
        else
            rState = id;
        if (id == 3)
            rState = this->md->aiPlayer->researchState(0x66);
        if (id == 4) {
            rState = this->md->aiPlayer->researchState(0x67);
            return rState == 1;
        }
    } else {
        rState = this->md->aiPlayer->researchState(id);
    }
    return rState == 1;
}
```

This form follows the PDB stack types and the original line bands. It has no
`volatile`, address-taking, pointer cast, union, wrapper, declaration-context
trick, or code-generation helper. The tested early-return rewrite was rejected:
it changed 139 bytes and did not improve the source evidence.
