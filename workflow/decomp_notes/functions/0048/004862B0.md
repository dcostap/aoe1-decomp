# Function notes: 004862B0 `place_avoid_objects`

## Root integration decision

The source pushes the zone output pointer before it reads the player pointer.
The original reads the player pointer first. The root changed this target
to `scratch` pending fault-order review for invalid objects.

## drift-042 review

### Behavior

The original body runs from `004862B0` through `004864E7`. The PDB lists the
`RGE_Object_Info_Line&` argument, long `inner_radius`, player receiver, stack,
coordinates, count, and zone. It maps `tile_y` to the incoming `inner_radius`
home. See `build/dossiers/004862B0_place_avoid_objects.txt`.

The body fills `search_map` with byte value `1`. It uses the low 32 bits of the
width-height product. It clears each land rectangle, initializes the local
stack, and fills it with candidate and random positions.

It maps every negative player ID to zero. It then pops a position before it
tests the remaining count. It checks terrain only when `terrain >= 0`, and it
compares the low five terrain bits. It converts tile coordinates to floats. It
truncates each master radius through `__ftol` and a signed 16-bit value. It
adds `0.5f` only when the radius remainder is positive.

It calls the master placement check with the original player, coordinates, null
obstruction pointer, and seven original flags. If that call returns false, it
removes the exclusion area. Group flag `0` creates one object, `1` calls
`place_group`, and `2` calls `place_cluster`. Other flags do not dispatch. The
function decrements the count after this failed placement check, then pops the
next candidate. It deinitializes the stack on each normal exit.

The original contains thirteen calls. The rebuilt body keeps the same call
order, targets, receivers, argument values, widths, and cleanup. The body keeps
the same frame, saved registers, return cleanup, branch counts, and function
boundary. The original and rebuilt listings match from offset `+0xBF` through
the end. They also match across the initial land-loop block.

The radius constants are local original executable values. `00571EDC` is
`+0.0f`; `00571EE0` is `-0.5f`. The rebuilt object has the same two values.
See `build/drift-042-rmm_obj/original_constants_00571edc.txt` and
`build/drift-042-rmm_obj/rebuilt_constants_004862B0.txt`. The stand-alone
function checker still marks one linked numeric dependency unknown.

### Open checks

The review used static listings. It did not run the game or test runtime cases.
The original loads the player-array entry before it stages the first
`pop_stack` output pointer. The rebuild stages one pointer first. This changes
fault timing if the player array is invalid, and a forged pointer could alias
the current stack. The probe did not change this code. Do not claim equal fault
order for malformed or deliberately overlapping object graphs without a
focused proof.

The original and rebuilt listings both store the y coordinate with
`fstp [esp+44h]`. The PDB maps `tile_y` to the incoming `inner_radius` home.
Confirm this stack-home label before changing local lifetimes.

No behavior defect was proved for a valid game object graph. No source repair
or new exact proposal is supported by this pass. Keep the existing registry
status unchanged. The fault-order and runtime checks above remain open.
