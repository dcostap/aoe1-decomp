## Behavior

The original packet is `inventory/functions/0054/00546A90_do_zone_map.txt`.
The function is `__thiscall`, returns byte `1`, and has one direct call to `00546BB0`.
The call target is `RGE_Zone_Map::do_zone_map_area`.

At `00546A99..00546ABB`, the original writes `0xFF` to exactly 255 bytes at `this+0x40C`.
It uses 63 dword stores, one word store, and one byte store.
`RGE_Zone_Map::zone_info` is 257 bytes, so the final two bytes are not reset.
The function does not reset the count cache at offsets `0..0x403`.

The original reads signed 32-bit map width and height from `this->map` at `00546AAC..00546AAF`.
It clears `zone_map_rows[row][col]` for `row < map_width` and `col < map_height` at `00546AC8..00546AE8`.
These dimensions are transposed from the map's conventional row/column layout.
The constructor allocates `map_height` row pointers, each with `map_width` cells.
For non-square maps, the clear loop can index outside the row-pointer array or row data.
The later traversal repeats this transposition.
This is an original bug and must remain.

The outer loop visits an index from zero while signed index `< map_width`.
The inner loop visits `x` from zero while signed `x < map_height`.
The terrain byte comes from `map_row_offset[outer_index]` at byte offset `row_offset+5`.
`row_offset` starts at zero and advances by `0x18`, the `RGE_Tile` size.
The byte is masked with `0x1F` before indexing the passability table.
The original compares that float with the eight-byte zero at `00577A20`.
`inventory/globals/all_globals.csv` records that address as double zero with bytes `0000000000000000`.

Before classifying an unassigned cell, the original resets the signed dword counter to zero when it is at least 255 (`00546B18..00546B20`).
It writes the counter byte to the root cell at `00546B68`.
It then calls `do_zone_map_area` with `this`, `x`, `group`, visibility `0/1`, and the counter byte.
The call pushes the arguments in reverse order at `00546B66..00546B6F`.
The counter increments only after the call returns at `00546B78`.
This assigns zone IDs `0..254`, then reuses zero.

The area call's third argument is passability classification, not the outer row index.
The second argument is the outer index and becomes the area routine's `y` coordinate.
`do_zone_map_area` checks the same zero threshold and visits four neighbors.
Its bounds use map width for `x` and map height for `y`.
Thus the transposed coordinates can also produce out-of-range reads on non-square maps.
The exact source body and original packet for that callee are `src/zone_map.cpp` and `inventory/functions/0054/00546BB0_do_zone_map_area.txt`.

If width or height is nonpositive, the signed guards skip the corresponding loops.
The function still resets 255 zone-info bytes and returns one.
There are no dimension clamps, table-length checks, or null checks.
Those omissions match the original.
No focused runtime test was practical.

## Source
